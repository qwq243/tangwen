# 语料：格式、标签、补卷

## `puzzles.json` 长什么样

顶层三个键：`version`、`host_role`、`puzzles`。

`host_role` 是给主持人的角色设定，整段拼进判题问句里（原文见文件）。`puzzles` 是 44 个
对象，每个的字段如下。拿《跳楼的女人》当例子：

```json
{
  "id": "jumper",
  "title": "跳楼的女人",
  "image": "images/jumper.png",
  "surface": "女人对世界感到绝望，于是决定跳楼。没想到跳下去的瞬间电话响了，她感到后悔，却来不及了。",
  "bottom": "丧尸病毒爆发，女人身边的人都变成了丧尸。她以为自己是世界上仅存的人类，绝望跳楼。跳下的瞬间电话响起，说明还有其他活人。后悔已经来不及。",
  "metaphor_map": [
    "绝望来自误以为人类灭绝，不是普通心理危机。",
    "电话响起证明还有其他活人。",
    "她没能活下来。"
  ],
  "facts": {
    "zombie_outbreak_happened": true,
    "she_thought_she_was_last_human": true,
    "phone_call_means_other_humans_live": true,
    "she_survives_the_jump": false,
    "call_was_an_ordinary_comfort_call_before_apocalypse": false
  },
  "cast": [
    { "name": "女人（她）", "sex": "女", "who": "叙述者；丧尸爆发后以为自己是仅存的人类，跳楼，跳下时电话响了" },
    { "name": "打电话的人", "sex": "未写明", "who": "电话那头的人，是个活人 —— 故事只用到「还有别的活人」这一点，没写是谁" }
  ],
  "keys": [
    { "id": "outbreak", "label": "丧尸爆发", "expect": true, "prompt": "世界是丧尸病毒爆发后。" },
    { "id": "not_last", "label": "并非最后人类", "expect": true, "prompt": "她误以为自己是最后的人类。" },
    { "id": "phone", "label": "电话是活人", "expect": true, "prompt": "跳下时电话响，说明还有其他活人。" },
    { "id": "dies", "label": "没能生还", "expect": true, "prompt": "她没能活下来。" }
  ],
  "difficulty": "中",
  "soup": "红汤"
}
```

几个字段值得单独说：

- **`surface` 是玩家能看到的一切**，`bottom` 永远不下发（结案或放弃时才给）。
- **`facts` 是判题的准头所在。** 它跟 `bottom` 一起喂给模型，键名写成英文 snake_case 的
  布尔断言，值就是真值。玩家问「她是最后一个人类吗」，模型靠查这张表判真假。
  写错一条，那一类问题就会一直判错，而且不容易发现 —— 这就是为什么补卷不能自动化。
- **`keys` 是进度条也是结案判据的一半。** `id` 是稳定标识（客户端跨轮带的就是它），
  `label` 是 chips 上显示的那几个字，`prompt` 是喂给模型判「问到没有 / 讲出来没有」的
  那句话。`expect` 是主持人期望的回答方向。
- **`metaphor_map`** 是汤面隐喻翻到汤底事实要绕的那几道弯，也是难度的组成部分。

## 难度：浅 / 中 / 深

写在每卷的 `difficulty` 字段里，**数据说了算，代码只负责显示**。算法在
`tools/difficulty.py`：

```
score = 关键点数 × 4 + 隐喻层数 × 2 + 事实条数      ≤31 浅 / 32~37 中 / ≥38 深
```

权重是按「哪一项真的让人卡住」配的：关键点数是这一卷**要问出几件事**，最硬；
`metaphor_map` 是汤面隐喻翻到汤底事实要绕几道弯；`facts` 是搜索空间的大小。

44 卷实测范围 18~48，两刀切在 31 / 38，三档 17 / 18 / 9 卷，**分数与档位严格单调**
（不会出现「同分不同档」）。觉得哪一卷不该是这个档，直接改那一个字就行；
`python tools/difficulty.py --write` 只补**还没有值**的卷，不会覆盖手改过的
（要重算全部得 `--force`）。加卷之后记得跑一遍，新增的卷目自己就补上了。

难度出现在五个地方：卷面（卷号旁边一枚描金小印，跟卷号同一行 —— 竖版从 `.plaque` 的
`top:85vw` 到 `.read` 的 `102vw` 只剩 ~67px，另起一行会压到汤面）、搜索列表每行、
搜索面板的筛选行、榜头、结案画卷。

## 汤色：清汤 / 红汤 / 黑汤

**难度是「要问出几件事」，汤色是「要咽下什么」—— 两个正交的轴**，所以是两个字段、两枚印。
浅卷可以是黑汤，深卷可以是红汤；挑卷的时候这两件事都得看得见。

口径的来源是知乎《海龟汤：一场脑洞大开的推理游戏之旅》第四节的「海龟汤常见分类」
（<https://zhuanlan.zhihu.com/p/2032042332867007256>，作者陶小敬，收录于「桌游与剧本杀」
专栏）。原文就三条，每类只有一句定性描述、一个例子都没给，也没说分类维度：

    清汤：无恐怖、无死亡，轻松脑洞。
    红汤：有尸体、命案，偏悬疑。
    黑汤：重口味、血腥、惊悚，慎玩。

**下面这三条是照原文那一句推出来的操作化，不是原文写着的**（原文没写维度，
所以「按什么切」这一步是这个项目补的，改口径就改这里）：

    清汤  汤底里没有人死 —— 轻松的脑洞、典故
    红汤  有人死（尸体 / 命案 / 亡者 / 灵异），但死法本身不是卖点
    黑汤  重口本身就是卖点 —— 对尸体或身体的处置（分尸、剥皮、食、寄生、拼接、
          活埋、换脑……），无论出没出尸体

44 卷判下来是 **清汤 3 / 红汤 17 / 黑汤 24**。这个分布不是配错了：这一套卷子本来就偏恐怖，
海龟汤几乎卷卷有人死，真正稀罕的是清汤。想让不玩恐怖的人也能进来，缺的是清汤，
补卷的时候按这个缺口补。

**为什么不像难度那样纯公式算**：难度那三项（关键点数 / 隐喻层数 / 事实条数）全是现成的数，
一算就准；汤色是语义判断 ——「有没有人死」能从汤底扫出来，「这个死法算不算重口」得读一遍。
所以 `tools/soup.py` 给的是**关键词提议 + 命中证据**，跟 `difficulty.py` 守同一条规矩：
**值以 `puzzles.json` 的 `soup` 字段为准**，已有的值不会被覆盖（除非 `--force`）。

关键词表是照着最初的 34 卷量出来的，**新卷看证据列、别只看提议列**。几个已知的粗细：
`手术` 本来在重口词里，但有一卷那台是性别重置手术，不是重口，所以拿掉了；「出租房」
那一卷的死亡写成「让他永远待在了天花板里」，靠自己那句「封进」才认得出来。

后来补进 10 卷时又验了一次这张词表，命中两处误判，都在 `puzzles.json` 里人工定了、
脚本照规矩把它们列进「不一致」等人复看：《蚊子》只因为汤底有个「血」字被提议成黑汤
（死的是一只蚊子、血是吸来的，该是清汤）；《日记》的「贴狗皮 / 用尸体做狗粮」没被认出来
（实际是黑汤）。**别为了消掉这两条去扩词表** ——「血」「死」在别的卷里是有效信号，
收紧一点就会误伤。

颜色只在 `web/styles.css` 顶上那三行 `[data-soup]` 里定义一次（`--sp` / `--sp-bd` / `--sp-bg`），
凡是带 `data-soup` 的元素都从那里取。清用苔青 `#8fae7a`、红用朱砂 `#c4563c`，都比原色提亮过
（深色墙上才读得出来）；**黑没有写成黑字** —— 夜馆本来就是深底，黑字看不见，改成
「墨底 + 朱边」：底比周围更暗读作黑，朱边就是原文那两个字「慎玩」。

## 人物表 `cast`

谁是谁、是男是女，由 `tools/cast.py` 管，写进每卷的 `cast` 数组。写表口径是
**只认材料写明的**：汤底有性别名词（妻子 / 哥哥 / 儿子…）或干净的第三人称代词（他 / 她，
「其他」不算）才写「男 / 女」，而且每条都要留一句原文当证据 —— 脚本会验它是正文的子串，
写不出证据就只能写「未写明」。

材料真没写的那一档不是缺陷：玩家问到就明说「不重要」，别让他反复试。

为什么需要这张表、它怎么影响判题、以及为什么它必须排在 `state` 的最后一位，
都写在 [judging.md](judging.md) 里了。

## 语料来源与补卷

**这 44 卷的作者是抖音的「许二木」。** 语料取自「许二木海龟汤文字版」合集
（在 B 站，id `rl999117`，一周三更）—— 那是文字版的抓取入口，不是原始出处。
最早的 34 卷和后来补的 10 卷是同一批稿子，只是补的时候作者又更了十几篇。

补卷是四步，前三步各有一条命令，第四步必须手工：

```bash
python tools/bili-import.py            # 抓合集 -> 按「汤面 / 汤底」拆条 -> 跟已有卷宗去重
python tools/difficulty.py --write     # 补 difficulty
python tools/soup.py --write           # 补 soup
python tools/cast.py --write           # 补 cast（人物表）
```

然后手工写 `facts` / `keys` / `metaphor_map`，最后：

```bash
python tools/suite.py                  # 全套界面自查
```

**第四步为什么不能自动化**：`facts` / `keys` / `metaphor_map` 是判题的准头所在，
`judge()` 把 `facts` 跟汤底一起喂给模型，十档印判得准不准全看这几个字段写得对不对。
这是逐卷读一遍手工写的活，写不出公式。所以 `bili-import.py` 只负责「哪些是新的」，
不负责入库。

**补完卷必须打一遍真接口。** schema 全对、`json.loads` 不报错，跟「判得动」是两回事。
补那 10 卷的时候探针逮到过一次真问题 ——《蚊子》只有两个关键点，玩家一句「我是会吸血的
动物吗」同时命中两点、一句话结案。这类问题只有打真接口才看得见。

**不是所有卷都被采纳。** 合集里的稿子有些是半成品（只有汤面没汤底）、有些互相重复，
去重那一关会把它们挑出来。去重同时看标题和汤面两条判据：只看标题会漏（《新房》入库时
改叫《出租房》），只看汤面也会漏（同一碗汤可以重写）。

### `bili-import.py` 里的两个坑

**不能直接打 `x/article/view`**：那个接口对这批稿子一律回 -352（风控），专栏页面本身又是
SPA 空壳（HTML 只有 3KB 外壳，正文全靠 JS 渲染）。唯一拿得到正文的是**动态 opus 详情
接口**，用列表接口给的 `dyn_id_str` 当 opus id。

去重的两条判据是：标题归一化后相同或互相包含，或者汤面 difflib 相似度 ≥ 0.62，
命中其一即判为已有。

## 封面

封面是增量加载的：开卷只等当前这一张（最多 1.8 秒），左右邻卷立刻预热，
顺着滑动方向再备两三张，空闲时才把其余卷慢慢补上，省流 / 2G 下只预热邻卷。

图片必须是 **webp + 同图 PNG 兜底**：`web/images/*.webp` 是正常加载的那份，
`*.png` 是浏览器不支持 webp 时的回退（占了大头，约 42MB）。两者的文件名只差后缀，
前端会自动回退，不需要额外配置。

生成新封面：提示词写在 `docs/design/prompts.jsonl`（一行一张，`out` 是文件名、
`prompt` 是提示词），风格要求见 `docs/design/image-style-guide.md`。出图脚本要你自己
指一个 OpenAI 兼容的生图网关：

```bash
IMAGE_BASE_URL=https://your-gateway/v1 python generate_covers.py       # 缺哪张出哪张
IMAGE_BASE_URL=https://your-gateway/v1 python generate_covers.py dorm.png
python make_webp.py                                                    # 生成 webp
```

`make_webp.py` 要 PIL（`pip install pillow`）—— 这是全项目唯一一个需要第三方包的脚本，
而且只在补封面时用，跑游戏和跑回归都不需要。

**封面必须贴着画框**，这条是能量的量的：`tools/frame-fit.mjs` 逐视口逐卷量偏差，
超过 1px 就报错。补完卷记得跑它 —— 最狠的裁切是《疯人院》（16:9 的封面被 0.81 的画框
裁到只剩 45%，刚过 0.45 的门槛），它是全库最贴边的一张，动 `--slot-*` 之前先看它。

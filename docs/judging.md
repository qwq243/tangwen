# 判题

玩家问一句，主持人要落一枚印。这一篇讲十枚印分别是什么、结案按什么判，
以及那些看着有点怪的阈值是怎么来的。**要改判题口径，先读完这一篇。**

## 十枚印

掌灯人只会落这几枚（`server.py` 和 `functions/api/[[path]].js` 里的 `HOST_LABELS`，
前端配色在 `web/styles.css` 的 `.stamp.*` 与 `.ledger .a.*`）：

| verdict | 印面 | 什么时候落 |
|---|---|---|
| `yes` | 是 | 对照汤底为真（含近义问法） |
| `no` | 不是 | 对照汤底为假 |
| `both` | 是也不是 | 命题分时点 / 分对象 / 分场景成立，两头都咬在汤底上 |
| `partial` | 部分对 | 一句话里有对有错，错的那半只是旁枝 |
| `close` | 接近了 | 摸到关键机制但还没说圆 |
| `irrelevant` | 无关 | 跟故事完全无关（问天气、问主持人本身），答了也对还原汤底没帮助 |
| `unimportant` | 不重要 | 问的确实是故事里的人或事，但材料没写，答对答错都不改汤底 |
| `unanswerable` | 问清楚点 | 压根不是一句能判真假的人话：乱码、半句话、纯情绪 |
| `refuse` | 不能剧透 | 玩家在直接要汤底 |
| `solved` | 结案 | 玩家把汤底说出来了，而且说对了 |

`refuse` 和 `solved` 不是模型选的，是 `judge()` 自己判出来的：前者看
`trying_to_extract` 那一问够不够高（且没结案），后者看下面那两条路。

## 结案：两条路，走通哪条都算

这是这个项目改得最多的一处，前后被三次实报推翻过，所以写得细一点。

**路 (1)：关键点被玩家自己讲出来、讲到够。**
**路 (2)：整段猜中**，他把整个流程讲了一遍。

**「关键点问到了齐」始终不是判据。** 那是进度条，两排 chips 里亮一格算一格。

翻成代码就是 `SOLVE_RULE` 那五个数，两条链路各有一份同名常量，
`tools/judge-check.py` 会逐值比对：

| 数 | 值 | 意思 |
|---|---|---|
| `full_guess` | 0.75 | `is_full_guess`：这一句是在**把汤底讲出来**，而不是在问一个点 |
| `guess_correct` | 0.78 | `guess_correct`：讲出来的版本抓住了核心机制 |
| `close_floor` | 0.45 | 「接近了」那一档的下沿，低于这条线就不假装接近 |
| `said_floor` | 0.43 | 单个关键点算「他自己讲出来了」的分线，路 (1) 用 |
| `keys_ratio` | 1.0 | 路 (1) 要讲出**多少比例**的关键点，难度就是这个旋钮 |

`keys_ratio` 是唯一该按「这次想多难」调的：`1.0` 是全都要讲出来，`0.75` 就是四个里
讲出三个即结案（条数 = `int(键数 × keys_ratio)`，向下取整）。另外四个数不是拍脑袋定的，
下面是量法。

路 (1) 和路 (2) 都会把 `bottom` 放出来，但落的话不一样：「关键点都说出来了。汤底封卷。」
和「说对了。汤底封卷。」。够一条不够另一条时**不结案**：机制说对了却没被当成整段汤底讲、
或者整段讲了但机制没说准，这两种都落「接近了」，前提是 `full_guess` 不低于 `close_floor`
（探针问题的 `full_guess` 只有 0.03~0.08，落不进这一档）。差太远才落「是 / 不是」。

### 为什么改成这样

**第一次是 2026-09-20。** 《柜中的孩子》里玩家一路问下来，最后一问把最后一个关键点问到了，
于是当场结案 —— 可他自己并没有想通，连「平行世界」都没往那儿想。老口径是
`solved = 所有关键点都问到了`，而关键点是靠探测性是非题一条条问出来的：问齐只说明料凑够了，
说没说圆是另一回事。所以把「问到」从判据里拆了出去。

**第二次是 2026-09-21 上午。** 报上来的是「无法结束，明明都答出来了」。这一次玩家把汤底
完整讲出来了，末尾顺手带一句「对不对？」，而 `is_full_guess` 那一问当时是拿**语气**判的
（判定它「是陈述，不是在问」）—— 这一句把 `full_guess` 打到 0.6~0.75 那条线上左右横跳：
同一句话连打两次，一次结案一次不结案，不结案那次落印还是「是」，看着就像游戏没听见
他说话。改法是那一问只认**内容**（有没有把机制讲出来，末尾的求证套话不影响），
探针才不算。实测 14 句 × 2 轮：改前 3 条不合预期，改后 0 条 —— 讲完整（含各种求证尾巴）
0.96~0.97，探针 0.03~0.05，讲歪了 0.07~0.16。

顺带把「机制说对了却没结案」单独标出来记一笔（`near_miss`，账房里的 `nearmiss`）。
**这一档应当恒为 0**：它涨起来就说明结案判据又在拿语气或措辞判事，玩家看到的就是
「我都答出来了它却不结案」。它是故障灯，不是指标。

**第三次是同一天下半场，口径对齐。** 原话是「因为这是一个小游戏，所以不要求最后用户
复述整个故事。难度可以不要太大：如果几个关键点都讲出来了就结案，如果判断用户已经猜出
整个流程也结案。」于是补上路 (1)：多了一组 `said_<关键点>` 问句（「这一句里有没有
**他自己**把这一点讲出来」），逐条累积 —— 客户端像 `unlocked` 一样把 `stated` 带回服务端，
讲够了就结案，用自己的话讲出来就算，不必串成一段。

### `said_floor` 那个数是怎么量的

0.43 是量出来的，不是拍的。真话最低 0.47（「世界交错了一次」这种间接说法），
杂音最高 0.39（「我是他妈妈吗」这种纯问句擦上来的那一下），取中点。

问句里「**只勾这句话真正讲到的那一条**」那句也不是修辞。不加它的时候，「我那次不算普通
流产，是胎儿跑到另一个世界去了」会被顺带给「我是他妈妈」也打 0.62~0.66，跟真话同一档，
杂音顶穿真话，靠调分线根本分不开。加上之后杂音掉到 0.27~0.39，真话还站在 0.47 以上。

**所以：动 `said_` 的问句就要重量这两个边界，别只改一个数。**

### 界面上跟着走的地方

改口径时这些要一起看：

- chips 有两档：`.key-chip.on` 是他**问到**了，再加 `.said`（右上角一枚小「说」）是他
  **自己讲出来**了。结案看的是后者，所以这一排就是「离结案还有多远」的读数。
- 他自己讲出一个关键点时弹一次揭示牌（kicker「讲 出 来 了」、计数「已讲出 x / y」）。
- 关键点问到齐但还没讲出来时，牌子和 chips 末尾那枚改成「把关键点讲出来 / 讲出来就结案」。
- 求灯带的方向用的是 `unlocked ∪ stated`，他刚说过的点不该再被提示。
- 入馆引导第四卡与首页简介是同一口径（`web/index.html` 的 `tour-card` 肆）。

### 验收

`python tools/judge-check.py` 不联网，把 `typesafe` 换成一个照剧本回话的桩，
直接喂判题输出，逐条断言：

    问齐不结案 / 整段讲对了才结案 / 关键点自己讲出来也结案 /
    问齐但只讲出一个不结案 / 跨轮累积（stated 带回来）能结案 /
    讲歪了接近了 / 差太远不是 / 机制说对了没讲成整段 → 接近了并标 near_miss /
    探针顶不穿这一档 / 直要汤底不能剧透 / 阈值压线与差一线 /
    没结案就不许把 bottom 带出去

它同时跑一遍双链路 parity（说明正文 + 五个阈值 + `solved` 的两条路 + `said_` 问句 +
「讲对了没结案」那一档的判定与记账 + state 字段顺序）。

`--live` 那一段打真接口，最后两条专盯「讲完整 + 求证尾巴」这一类，而且**各打两轮** ——
那个故障本来就是抖出来的（同一句话这次结案、下次不结案），单轮过不算过。

界面上那一档（chips 的「说」加揭示牌计数）钉在 `tools/effect-shot.mjs` 的第 1b 节。

## 判题那条不许换、不许退

`model: "jev-latest"` 写死在两边的常量里（`server.py` 的 `TYPESAFE_MODEL`、
`functions/api/[[path]].js` 的 `JUDGE_MODEL`），没有环境变量入口，也没有备胎模型。

因为十枚印的准头全在这一颗模型上：`pick_host` / `pickHost` 里那几条阈值
（`both >= 0.3`、`min(yes,no) >= 0.18`、`yes+no >= 0.45` …）都是照着它的概率分布量的。
换模型等于换一套判题口径，阈值全部作废，而且症状是「偶尔判错」这种最难查的。
想换，就必须连阈值一起重新量。

**除了判题，别的模型调用一律走 Cloudflare Workers AI 的免费额度。**

## 三件容易被判错的事

### 「是也不是」为什么要单独成档

题目复杂时，一问的答案本来就可能是「一半是、一半不是」。比如汤底里这个人死过一次又
活着回来，问「他死了吗」，答「是」答「不是」都是错的。

旧版 `pick_host` 是 `yes_p + no_p >= 0.45` 就直接取大的那个，正好把这种题判成错的那一半。
现在只要 `both` 的概率够高、且 yes / no 也都不低，就先认 `both`。

「是也不是」在关键点判定里和 `yes` / `no` 同等对待 —— 题目本来就只有一半是「是」。

### 「材料没写」不是「问清楚点」

`unanswerable` 这一档印出来的字是「问清楚点」，意思是**怪玩家没说清**，
不是「这题我答不上来」。但模型读到「汤底和 facts 里都没写这件事」时，给的正是
`unanswerable` 的最高分。

实测「跳楼的地点是办公楼吗」在旧口径下是 `unanswerable .51 / unimportant .43`，
落印成了「问清楚点」，等于让一个问法完全清楚的玩家替模型的为难背锅。

两头都改了：`criteria` 里写明「材料里没写不是这一项」，`pick_host` / `pickHost` 再加一道
软档回收 —— 模型自己选了 `unanswerable`（或回了个档位外的词）时，只要「不重要 / 无关」
里有一个够重（`SOFT_RESCUE_MIN`）且追得上 `unanswerable` 的六成（`SOFT_RESCUE_RATIO`），
就落那个软档。两条线都是照 `jev-latest` 在这类题上的实测分布量的。

乱码、半句话照旧落「问清楚点」，没有被回收。

### 身份类问题先看人物表，不许靠汤底代词猜

「爱人是男的吗」这种问题以前没有任何 ground truth 可查：state 里只有事件（`facts`）和
隐喻（`metaphor_map`），「谁是谁、是男是女、什么关系」一直是空的 —— 44 卷里 37 卷的
`facts` 连一条身份断言都没有。

实测《怀孕》那卷：「爱人是男的吗」回 `unimportant .65 / yes .23`，「ta 是男的吗」同一问
连打三次在「是」与「不重要」之间跳，问「是女的吗」也回「不重要」，两个方向都是软档，
玩家问不出任何东西。

改法分两层，一层在数据、一层在口径：

- **数据**：`puzzles.json` 每卷多一张 `cast` 表（谁是谁、性别、一句话身份），
  由 `tools/cast.py` 管。写表口径是**只认材料写明的**：汤底有性别名词（妻子 / 哥哥 /
  儿子…）或干净的第三人称代词（他 / 她，「其他」不算）才写「男 / 女」，而且每条都要留
  一句原文当证据 —— 脚本会验它是正文的子串，写不出证据就只能写「未写明」。
  材料真没写的那一档不是缺陷：玩家问到就明说「不重要」，别让他反复试。
  现在 44 卷 145 条：写明 97、未写明 45、跨阶段 3（双性人、换身体、女与小孩）。
- **口径**：`BASE_QUESTIONS.host_answer` 多一条 `identity` 说明 —— 身份题先看 `cast`，
  写明了的按它判真假，**玩家把性别问反了落「不是」，不许落「不重要」**；汤面用
  ta / 爱人 / 朋友 / 同学 / 有人 这类中性称呼不等于材料没写（那是汤面故意藏的说法）；
  `cast` 标「未写明」、或 `cast` 里根本没这个属性，才落软档；同一个人物的身份在一局里
  固定，正反两个方向的问法必须一是一否，也不许跟 `recent_history` 里落过的印打架。

### `cast` 要排在 state 的最后一位

这不是排版洁癖。《怀孕》的「怀孕的是爱人吗」在「`cast` 放在 `facts` 后面」时稳定答「是」
（yes .52–.58），放到末尾后稳定答「不是」（no .63–.73）—— 交错 4 轮、4:4 是这么来的。
身份题两种顺序都满分（18/18），所以按事件题那半边定了末尾。

**改顺序要连两边一起改**（`server.py` 的 `judge()` 与 `functions/api/[[path]].js` 的
同名函数），`tools/cast-check.py` 开头有一道不联网的断言会比对两边的说明正文与字段顺序，
只改一边它直接报红。

### 「指认」和「真假」也要分开

中文里这两种问法长得几乎一样，但期望的印面正好相反。「怀孕的是爱人吗」「怀孕的那个是
ta 吗」问的是**人是谁**，落指认：指的是那个人就答「是」，哪怕汤面那句话是假的（「爱人」
就是汤面里怀孕的那个）；「爱人怀孕了吗」「他在唱歌吗」问的是**那件事成不成立**，
落真假：汤面是假象就答「不是」。

没写这条之前，《怀孕》的这两个问法在同一次会话里会给出互相矛盾的印。`identity` 那段里
有这条规则，`tools/cast-check.py` 的 `LAYER_CASES` 钉了 13 条这样的问法。

身份题的验收是 `python tools/cast-check.py`，全库 303 问：写定的 194 问一是一否、
未写明的 90 问都落「不重要」、3 个跨阶段条目另写 6 条显式用例、5 卷 13 条指认 / 真假
分层用例。想看「只有说明、没有人物表」会怎样，跑
`python tools/cast-check.py --no-cast --quick`：同一批问题落错 13/76，错的清一色是
「该判真假却答不重要」。

改身份这条要动三处：`tools/cast.py` 的 `CAST` 表、`tools/cast-check.py` 的期望、
以及两边判题说明里的 `identity`。

## 改这一组档位要动哪些地方

加一档、改一档名字、调一个阈值，都要同时动这几处，**漏一处就是两条链路不一致**：

- `HOST_LABELS`（两边）
- `BASE_QUESTIONS.host_answer.criteria` / `bias` / `identity`（两边）
- `pick_host` / `pickHost`（两边）
- `web/styles.css` 里的 `.stamp.*` 与 `.ledger .a.*`

`tools/effect-shot.mjs` 开头有一张 `VERDICTS` 表会挨个喂一遍，漏了哪一档会直接报出来。

改结案口径（`SOLVE_RULE`）还要连带上：

- `BASE_QUESTIONS` 里 `is_full_guess` / `guess_correct` 的说明，以及 `build_questions` /
  `buildQuestions` 里 `said_` 那组问句的措辞（动它就重量 `said_floor` 的两条边界）
- `/api/ask` 两端的入参（`stated` 要跟着收、跟着回）与前端 `web/app.js` 的 `statedMap`
  （存档、回报、chips 的 `.said`、揭示牌文案）
- `tools/judge-check.py` 的期望（离线档位 + `--live` 那几条）、`tools/effect-shot.mjs`
  第 1b 节、`tools/admin-check.py` 的桩与断言
- **两处记账**（`bump_track` / `bumpTrack` 的 `nearmiss` 白名单与判据）

除最后一条外，parity 都会逐条查，漏一边当场红。

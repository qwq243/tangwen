# 界面

前端是原生 HTML / CSS / JS，没有框架没有构建。`web/index.html` 一份 DOM，
两套布局靠 CSS 切。这一篇讲那几套坐标、两套布局的门槛，以及改界面时会踩的坑。

## 两套坐标

横版舞台 1536×1024，竖版 1024×1536，位置全部落在 `web/styles.css` 顶上的 CSS 变量里：

| 变量 | 含义 |
|---|---|
| `--slot-*` | 中央金框内窗 |
| `--wing-y` `--wing-h` `--wing-w` | 左右侧墙画框**可见**的那部分内窗 |
| `--frame-pad` | 金框画出来的边比内窗宽出的那截（横版单边 23px） |
| `--dossier-*` | 右侧「询问记录」面板的位置和宽度 |
| `--nav-size` `--nav-gap` | 导航箭头尺寸、它到金框的气口 |

横版与竖版背景图不是同一张构图，两套值不能混用。侧墙里的图按容器 4 倍宽渲染再裁掉外面，
只露画框可见的那一条。

**导航箭头**横版是贴着中央金框外侧对称站的（`--slot-x` − `--frame-pad` − `--nav-gap` −
`--nav-size`）。为什么不贴舞台边？因为右边那枚会被「询问记录」面板压住 —— 面板底色半透明，
箭头会在下面透出半个影子，看着像坏了。`--nav-gap` 就是两边各留的 40px 墙面色。
竖版另算：记录面板挪到屏幕下方居中，两侧没东西抢位置，所以仍按侧墙画框外沿留气口。

## 竖屏两套布局

上半（卷号 85vw、汤面 102vw）按**宽度**走，底部那一摞（输入条 4vh 起往上）按**高度**走。
屏幕一矮就没有第三空间了 —— 汤面和记录面板抢同一段，键盘再一顶整页就糊。

所以竖屏有两套，由 `app.js` 的 `syncLayout()` 二选一：

| | 用在哪 | 长什么样 |
|---|---|---|
| 画廊 `.stage.tall` | `height >= 1.375 × width + 180` | 画卷居中、侧墙、印章、底部记录面板 |
| 紧凑 `.stage.compact` | 屏幕矮了，或者键盘弹起 | flex 六段：顶栏 / 画卷横幅 / 汤面 / 记录 chip 条 / 状态 / 输入条 |

那个门槛不是拍脑袋的比例，是从 CSS 常量解出来的：汤面 `top 102vw` +
`max-height min(30vw,24vh)` 最低触到 132vw，底部一摞固定占 `4vh + 100px`，记录面板保底
64px，解 `H - 0.04H - 100 - 132vw - 64 - 8 >= 0` 得 `H >= 1.375w + 180`。

门槛曾经是 269，后来降到 180：354×676 对比 440×956，画廊才是对的，小屏也该有画框。
**门槛和 `.stage.tall .dossier` 的 max-height 保底是同一道方程**（保底 64px 对应门槛 +180），
两头必须一起改，否则面板长满记录时会压住汤面。原来按 150px 面板推的 +269 会把
354×676 / 390×725 / 535×912 全推进紧凑态。现在仍进不了画廊的：360×640 / 375×667 /
412×732 / 400×600 / 480×720 / 320×520 / 820×1180。

**改这几条 CSS 常量（`--slot-y` / `.read` / `.dossier` 的 `bottom`）时，记得回头改
`app.js` 的 `GALLERY_MIN_RATIO` / `GALLERY_MIN_PAD`，然后跑一遍 `fit-scan.mjs`。**

**探针里也抄了这两个数，抄了就一定会过期。** `tools/fit-scan.mjs` 有一份
`GALLERY_MIN_RATIO` / `GALLERY_MIN_PAD` 的拷贝（它要算「该不该紧凑」）；
`tools/hint-check.mjs` 的紧凑态测试高度 `COMPACT_H` 是从同一道方程算出来的
（原来写死 730）。门槛从 269 降到 180 那次，这两处没跟着改，`suite.py` 里 fit-scan 与
hint-check 白红了一轮，报的却是「图片位置」之类的界面症状，很容易以为是画布代码坏了。
**再看到这两个脚本红，先对一眼门槛数字。**

### 紧凑态的三条底线

**导航、声音、记录不能藏。** 回答只渲染在 `.ledger` 里（外加一个 2.4s 的印章），
把记录藏了就等于「问完看不到回答」。所以紧凑态把导航和声音绝对定位进顶栏，
把记录压成一条横向可滚的 chip 条（每条 = 问句 + 结论，最新的在最左）。

**`.frame-window` 要保持 `position: relative`。** 印章是它的绝对定位子元素，
改成 `static` 印章会改挂到 `.stage` 上、跑到屏幕正中间糊在汤面上。

**背景那幅展厅画在紧凑态必须压暗**（`.stage.compact .hall::after`），画卷自带金线细边。
那幅画是按横版等比舞台画的，金框在画面中央 1/3；紧凑态舞台是任意比例加 `cover` 裁切，
画出来的框投影随比例漂移，永远对不齐全幅画卷 —— 535×912 实抓：框底梁从画卷下缘露出来、
框的两侧又被画卷盖住，看着就是「图片超出相框」。压暗后框不再可辨，画卷那圈 1px 金边
就是它自己的框，**框跟着图走，任何比例都贴着**。

### 紧凑态的版面：画卷吃富余，「画卷 + 汤面」当一整块

原先画卷是固定的一条横幅（`min(38vw, 32%)`，390 宽只有 148px），富余全被推给下面的
`.read`，汤面靠 `margin: auto 0` 在那一大块里居中 —— 结果是「上下一两百像素空带 +
两行 14px 小字」，配上顶栏 / 记录条 / 输入条三条贯通的实心 1px 横线，整页念起来
就是一张课程表（实测 390×730：汤面上下各 198px 空白）。

现在：

- **画卷自己长起来吃富余**（`height: min(78vw, 44%)`，`flex: 0 1 auto` 让它真挤不下时
  才给汤面让位），汤面改成「贴着头像往下、自己多高就多高」（上限 46% 封顶，超长在内部滚）。
- **富余落在这一块的外面，而不是在里面掏两个洞**：`.frame-window` 挂 `margin-top: auto`、
  `.read` 挂 `margin-bottom: auto`，上下两个 auto 外边距把富余对分，「画卷 + 汤面」
  作为一整块在顶栏与记录条之间居中。`compact-scan.mjs` 会断言这两个留白对称。
- **三条实心横线换成「两头淡、中间亮」的金线**（`.plaque` / `.dossier` / `.dock::after`），
  分段还在，但不再是网格。
- **汤面 14px → 16px**。14px 宋体在手机上偏小，正是「汤面字很小」的由来；
  16px 也正好是 iOS 里不会再触发输入框自动放大的那一档。

**改 `position` 类型时必须把四个偏移量一起显式置 `auto`。** 为了挂那条金线的 `::after`，
紧凑态的 `.plaque` / `.dossier` / `.dock` 从 `static` 改成了 `relative` —— 而横版竖版
遗留的 `top: 68.8%`（`.plaque`）、`top: 85vw`（`.stage.tall .plaque`）、`bottom: 4.6%`（`.dock`）、
`bottom: 4vh`（`.stage.tall .dock`）在 `relative` 下不再是空话，会真的把这两条推走
（实测顶栏被推到 332px 处、跟画卷叠在一起，输入条也被顶起来压住记录条）。

## 写界面时的几条硬约束

### 展示层级：解锁 < 结案

关键点解锁（`.reveal-plate`）是一条「通知」，结案（`.finale`）才是「结论」。
两处字号是刻意分开的，`.reveal-title` 必须小于 `.finale-title`：

| | 横版 | 竖屏 |
|---|---|---|
| `.reveal-title` | `clamp(21px, 2.4vw, 34px)` | `clamp(19px, 5.4vw, 26px)` |
| `.finale-title` | `clamp(30px, 3.8vw, 46px)` | 同左（手机取到 30px） |

竖屏那条 `.stage.tall .reveal-title` 是最容易写崩的地方 —— 它曾经是
`clamp(26px, 8vw, 40px)`，在 390 宽的屏上算出 31.2px，比结案的 30px 还大，
解锁那一下比结案还响。`effect-shot.mjs` 里有一条断言专门钉这件事，改字号后跑一遍。

`.finale-scroll` 的 `padding-bottom: 136px` 是给朱印留的固定带，**不能挪到 `.finale-body` 上**。
汤底最长 248 字，手机上 body 会滚；预留一旦做在内容末尾，滚动时它跟着滚出视野，
朱印就会压到最后几行正文上。同理 `.finale-scroll` 上不能挂外侧 `box-shadow` ——
展开动画用的是 `clip-path`，会把落在边框盒外的阴影一并裁掉。

`.reveal-plate` 有 `max-width: min(78%, 620px)`。最长关键点标签 7 字，一次解锁多条时用
「 · 」拼起来，没有这个上限会直接顶到屏幕边。

### 紧凑态里不许把某个功能的「出口」`display: none` 掉

紧凑态是按「屏幕不够高」裁出来的，裁的应该只是装饰（`.motes` / `.wing` / `.seal` /
`.mic-cap` / `.heard`），凡是「玩家点了按钮要看到东西」的元素都必须留一个出口，
而且那个出口得是真能显示的（别再挂在一个自己也是 `display: none` 的容器上）。

求灯就踩过这个坑：紧凑态把 `.hint-line` 和 `.hint` 同时藏了，点求灯等于什么都不会发生，
而「孤灯」已经扣掉了 —— **出口全堵的功能比没有这个功能更糟**。改紧凑态之前先想清楚：
这个功能的结果，在紧凑态落在屏幕上哪一块？

出口还得落在玩家找得到、且不盖住正文的地方。同一个功能改两次位置就是这一条：求灯按钮
从记录面板里挪到底栏（反馈是「注意不到」），提示正文从「记录条最后一行 + 屏幕正中浮层」
挪到记录方框第一行（反馈是「不明显」「挡住汤面」）。判据不是「屏幕上有没有这个东西」，
是**玩家看不见的那一处不算出口**、**盖在汤面上的那一处是负分**。

量它的是矩形相交，不是肉眼：`hint-check.mjs` / `finder-hint-check.mjs` 里那几条
`overRead` / `overDock` / `aboveLedger`。

### 给读屏留一个出口

印章（一闪就没）、记录条（滚动区）、汤底（画卷里）都只有「看」这一个形态，所以有一个
专门的 `#srVerdict`（`.sr-verdict`）来播报回答、解锁、提示和汤底。

它按读屏专用的老写法做（1×1 + `clip-path: inset(50%)`）：**别改成 `display:none` 或
`width:0`**，藏起来的 live region 不会被播报；也别把它挪进某个会 `hidden` 的容器里。
`tools/hint-check.mjs` 的 `findText()` 会显式跳过它，免得它把「提示行被藏起来了」
这种真故障盖成假绿。

## 输入框不能丢焦点

手机上「点输入框，输入法闪退」—— 卡一下，然后整句话敲不进去，顶部搜剧本和底部问句
两个框都有。`tools/mobile-input-check.mjs` 就是照着这条写的，量出来是同一类事、
三个不同来源，**全都是「聚焦之后可见性或布局变了」**：

| 探针量到的现场 | 原因 |
|---|---|
| 搜剧本框 `focusin` 之后紧跟 `focusout`、activeElement 变 BODY | 键盘弹起把可视视口压到 560 以下 → `syncLayout` 翻紧凑态 → `.stage.compact .finder .finder-box { display: none }` 把正在输入的框藏了 |
| 名字框的 `focusout` 出现在 `vv.resize` **之前** | `@media (max-height: 560px) { .stage.tall .dossier { display: none } }` 是纯 CSS，比 JS 翻布局更早生效，整块记录面板连着里面的输入框一起没了 |
| 本来就处在紧凑态时怎么点都没事 | 键盘弹起不需要翻布局，没有「变」这一步 |

修法都在 `web/app.js` 的 `syncLayout` 一带：

1. **翻之前先揭出口**（`revealFocusOutlet`）：有焦点的输入框要是会被紧凑态藏起来，
   先把它在紧凑态里的出口打开（`#findInput` → 加 `.finding`，紧凑态的搜索框本来就在
   浮层里，这也正好符合「紧凑态的搜索就是个浮层」这个语义）。
2. **翻完把焦点接回来**（`keepFocus`）：真掉了就 `focus({ preventScroll: true })` 接回去。
3. **没有出口的输入框，正在输入时干脆不翻**（`COMPACT_INPUT_OUTLET`）：`#playerName`
   在紧凑态整行是 `display: none`，翻过去等于丢焦点 —— 它聚焦期间既不藏面板也不翻布局
   （stage 挂 `.naming`）。
4. `styles.css` 里 `@media (max-height: 560px)` 那条加了 `.naming` 例外（见上表第 2 行）。

三条别踩的坑：

- **不要想在 `pointerdown` 里「提前」把布局切好。** 试过，是错的：切布局会让手指底下
  那个输入框当场挪位置，等 touchend 合成 click 时坐标已经不在它身上，点击直接落空，
  比原来的毛病更坏（探针第 1、3 组当场红）。
- **`focus` 处理器里那个 `stage.classList.contains("kb")` 是死守卫**：`.kb` 全项目没人加
  （CSS 里也没有），所以它恒为假 —— 每次聚焦 260ms 后都真的滚了一下 `scrollIntoView`，
  而那一下正好落在输入法弹起的时刻。现在按真正的那件事判（`compactOn`）。
- **加任何新输入框，先回答「它在紧凑态落在屏幕上哪一块」**（和求灯、计时同一条规矩）。
  答不上来就先别加；`COMPACT_INPUT_OUTLET` 那张表就是这句话的落地。

还有一条是**探针自己的坑**：模拟键盘的高度不能写「保底 320px」—— 横屏 844×390 扣掉 320
只剩 70px 可视区（真机上不存在这种键盘），舞台按 3:2 缩成 105 宽、搜剧本框塌成 0 宽，
量出来是个**假故障**，查了半天才发现是参数不现实。现在按 `min(45%, 420px)` 算。

## 图片必须贴着画框

**这条不是「看着差不多」，是能量的量。** `tools/frame-fit.mjs` 逐视口逐卷量三个数：
当前那张图的矩形对比 `.frame-window` 的内窗矩形、`strip` 的位移对比一个画框宽、
封面的 `cover` 缩放因子对比两轴尺寸，偏差 > 1px 就报错。现在 9 个视口 + 「改宽 / 换卷 /
竖横互转 / 键盘态」几条路径 + 44 卷逐卷扫，281 项断言全绿。补卷之后要重跑。

改 `.slide` / `.strip` / `--slot-*` / `syncLayout` 之后**先跑它，别靠肉眼**。

三条容易掉链子的地方，已经分别钉住了：

1. **画卷宽度 = 滑动步长。** `setOffset` 取的是 `frame.clientWidth`，宽度变了不重算，
   strip 就停在旧步长上，画框里会同时露出上一张的半边（一条竖缝）。
2. **手机横过来不是键盘态。** `keyboardOpen()` 原来只看「可视高度 < 480」，而横屏手机的
   高度本来就 < 480，于是 844×390 被当成键盘态：方向不再重判、停在 `.stage.tall` 上走
   紧凑布局，画卷变成 844×172 的一条横幅，16:9 的封面被裁得只剩 20%。现在多一条前置
   判断 —— **宽度明显大于高度时一定不是键盘**（软键盘只会压高度，不会让宽超过高）——
   横屏走的是横版画廊，裁切可见面积回到 81%。
3. **`.slide` 的份额必须是画框宽的 1/3，且 `object-fit: cover`。** 份额错了会有缝，
   换成 `contain` 会露黑边（那就成「图片比画框小」了）。`frame-fit.mjs` 两条都断言。

### `syncLayout` 里那条「宽度变了也要重算偏移」

原先只在**换布局**（画廊 ↔ 紧凑）时才重算，宽度变了但模式没变就不管 —— 于是 strip 停在
旧步长上，画框里会同时露出上一张的半边，一条竖着的接缝。手机在微信里打开时最容易撞上
（webview 宽度会变、高度变化更大，但两边都还在紧凑态）。

现在改成「宽度变了或换了布局都补一下」，但**只在宽度变化时**才补：可视高度在手机上会
因为地址栏收放频繁抖动，每次抖都 `setOffset` 会把玩家正在拖的那一下打断。

## 搜剧本

44 卷顺着滑太慢，顶上给一条搜索（`#finder`）。索引四样：卷名、卷号（`02` 和 `2` 都认）、
汤面正文、汤色（敲「黑汤」就把这一类列出来）。命中按「卷名 → 卷号 → 正文 → 汤色」排，
同档按卷序；已结案的挂一枚「已结案」，正停着的那一卷卷名标金。点结果直接落卷，
不走推拉动画 —— 搜索是「翻到第几卷」，不是「顺着往下翻」。

**点一下搜索框（或放大镜那枚图标），面板连着下面两行分类就出来**，不必先敲一个字。
`app.js` 里分两个动作：`revealFind()` 只把面板露出来、不动输入框里的字（点进来看有什么
可挑的），`openFind()` 是「重新搜一次」、会清空输入框（按 `K` 与点放大镜走这条）。
一处要留神：**揭了就得 `renderFind()`** —— 少了这一步会留下「`findOn` 为真但列表收着」
的死状态，之后 `openFind()` 因为 `if (findOn) return` 直接返回，放大镜怎么点都打不开
（紧凑态实测踩过，`tools/finder-hint-check.mjs` 第 6 段钉着）。

面板的**第一行是筛选行**（`li.ftags`，sticky）：汤色三枚 + 一条细分隔线 + 难度三枚，
共用一个「全部」（点它两道筛选一起清）。它为什么住在 `#findList` 里面？这样它跟列表同框、
同一块滚动区，不用另算一块绝对定位的高度，也就不动 `.finder` 自身的高度 —— 而
「`.finder` 高 34px、落在顶部一条带里、不压画卷」正是 `tools/finder-timer-check.mjs`
的 A1 三条断言量的东西。代价是 `#findList` 里除了结果行还住着两个不是结果的 `li`
（`li.ftags` 和空态 `li.empty`），**取结果行一律用 `li[data-i]`**。

**不敲字就是「翻这一类」**：`findHits("")` 返回整类、且不吃 `FIND_MAX` 的 24 条截断
（敲了字那是「搜」，截断才有意义）。所以按 `K` 打开时亮着「全部」、下面列的就是全部 44 卷。
筛选过再搜的空态要说清是哪一层空的：「`清汤`里没有`圣诞`」，不是「没有这一卷」。

两种形态、**一份 DOM**，靠 CSS 切（`app.js` 的 `openFind` / `closeFind` 只管加不加
`.finding`）：

| | 摆在哪 | 长什么样 |
|---|---|---|
| 横版 / 竖版画廊 | `.finder` 绝对定位在顶墙中央（横版 `top: 3.2%`、竖版 `top: 3vw; width: 62vw`） | 输入条常驻，敲字或按 `K` 出面板 |
| 紧凑态 | 顶栏图标群最左（`right: 168px`） | 只留一枚放大镜，点开整屏浮层（`.stage.compact.finding`），点空白 / Esc 收起 |

紧凑态为什么非得是浮层：顶栏那一行**没有横向余量**再塞一条输入框（卷号 + 标题 + 换卷 ×2 +
声音 + 灯已经排满），而且 `flex-direction: column` 里同级元素只占一行，没法把输入框并进
那一行。所以 `.plaque` 的右侧留白从 164px 加到 200px 给放大镜腾位，输入框本体只在浮层里出现。

浮层用 `position: absolute` 而不是 `fixed`：`.stage.compact` 自己带
`transform: translateY(--vp-top)`，`fixed` 在里面会改以它为基准，反而算不准。

快捷键：`K` 打开（宽屏直接聚焦输入框，紧凑态展开浮层），`Esc` 收起。搜索框里打字**不会**
触发 `m` / `h` / `?` / `k` 那些单键快捷键 —— 全局 keydown 里对 `#findInput` 先 return。

**`closeFind()` 不重置汤色筛选**（输入框也不清）：筛着的汤色是一种「正在浏览哪一类」的
状态，再按 `K` 回来时还是那一类才对；两者在面板里都看得见（选中的那枚印是亮的）。
真正清空两样的是「×」，所以它的显隐判据是 `!findInput.value && !findSoup`（`syncFindClear`）——
只要还有一样没清，它就得在，那是唯一的清空出口。

## 计时：手上时间

排行榜上的「用时」不是墙上时间，是**手上时间**：从开这一卷起算，只要长时间没有任何操作
（提问 / 打字 / 拖动画框 / 点按钮 / 从别的 App 切回来）就停表，下一次操作自动接着走，
暂停的那一段直接丢掉。出门吃个饭、手机息屏、切去聊天再回来，用时不会凭空涨掉几千秒。

- 阈值 `IDLE_MS` 默认 **60 秒**（`app.js`「计时」那一段）。探针要验停表不可能真等一分钟，
  往 `localStorage` 塞 `fengcun.idleMs`（毫秒，≥200）就能改，
  `tools/finder-timer-check.mjs` 用的就是这个口子。
- 判「有操作」用一组 window 级的 passive 监听（`pointerdown` / `keydown` / `wheel` /
  `touchstart`），所以**任何**点击都算，不用逐个控件挂钩。切走、息屏走 `visibilitychange`
  立刻停，回来接上。
- 状态只有一台表（同一时刻只在解一卷），换卷时 `startClock` 先把上一卷结清。
- **停表必须看得见，两套布局各有一个出口**（和求灯同一条规矩）：画廊态是 `#elapsed`
  前面的「∥」加变暗，紧凑态 `#elapsed` 是 `display: none`，靠 `.meter` 里的 `#pauseTag`
  「停表」那枚小签兜住。两个标记在 `syncPauseTag()` 里同帧翻，不然要等下一次 1s 轮询
  才看得出变化。
- 累计值存进 `fengcun.progress` 的 `active`（毫秒，按卷），和 `history` 一起落盘；
  `pagehide` 会先 `settleClock()` 再存。

### 结案那一刻要做的四件事

这一条是实报「结案了没结算、榜上没有我、还在记时」之后钉下来的。

1. **把表摘下**（`stopClock()`），不是暂停。`pauseClock()` 只是暂停，下一次 pointerdown
   （点掉结案画卷那一下就是）会被 `touchClock` 接回去接着走 —— 这就是「还在记时」。
   `stopClock()` 把 `clock.id` 清空；`startClock()` 另外拦一道：`solvedSet` 里的卷不再起表。
   摘表要在 `submitScore()` **之前**，成绩里的「用时」读的就是 `elapsedMsOf()`。
2. **停表标记不挂。** 结案之后的时间是结清的定量，不是「暂停中」，所以 `#elapsed` 不带「∥」、
   `#pauseTag` 也不出来。两个出口共用同一个判据 `pausedNow()`，别各判一套。
3. **成绩要在推画卷之前交**（`submitScore` 先 await，再 `setTimeout(showFinale, 480)`）——
   画卷里那句「你是第 N 位结案」要用成绩的返回值。网络卡住时给它 2.5 秒上限：
   超了就先推画卷（少那一句），成绩回来再补写。
4. **排行榜面板要先揭层再取数。** `loadBoard()` 开头有一条「层关着就直接返回」，
   而 `setBoard()` 原来是先调 `loadBoard()` 再揭层 —— 于是**第一次打开排行榜永远是空的**，
   只有「开着面板换卷」那次才会填上。玩家看到空榜，就以为成绩没结算，其实那一行早就写进
   服务端了。这条由 `tools/solve-check.mjs` 钉住（它同时验服务端那一行）。

## 量布局的小工具

改坐标别靠肉眼估：

```bash
# 多视口量元素坐标 / 间距 / JS 报错 + 截图
node tools/probe.mjs http://127.0.0.1:8765/

# 在 PNG 的一行带里扫「金色」列，量画框真实外沿（自带 PNG 解码，不依赖第三方库）
node tools/pixel-scan.mjs tmp/_shot/probe_desktop_1440x900.png 235 544 0 full
```

`probe.mjs` 的 `gaps` 就是判断「有没有贴太近 / 有没有被面板压住」的依据：
`prevToWin` / `winToNext` 是两个箭头到中央金框内窗的距离（还要减去 `--frame-pad`），
`nextToDossier` 是右箭头到记录面板的距离，负数就是压上了。

其余探针见 [testing.md](testing.md)。

# 求灯（AI 提示）

左下角有一盏灯，默认关着。开了之后底栏会多出一枚「求灯」，点一次要一句提示，
代价是这一卷的结案不挂「孤灯」勋章（`used_hint` 会写进排行榜）。

求灯是可选功能。没配任何凭据也能用，只是每次都回同一句兜底：

> 对照汤面里最不对劲的那一句，问它是不是字面意思。

## 按钮为什么在底栏

2026-09-20 之前它在「询问记录」面板里当一行，虚线框、宽度 100%，夹在记录和提示行之间。
反馈是「不要在方框里面，用户注意不到」。现在这枚灯牌（小灯泡 + 求灯两个字）排在
`[输入条 问] [求灯] [麦克风]` 的中间一列，不在任何方框里，玩家正要提问时视线正好落在这行。

底栏是三列 grid，求灯那列是 `auto`，灯灭时它 `hidden`、整列自己塌成 0，所以开关灯不会
让输入条跳一下。底栏的高度本来就由麦克风定（横版 56 / 竖版 48 / 紧凑 46），40px 的灯牌
顶不高它。**往这一行加东西之前先记住：别把这一行撑高。**

## 提示落在哪

**记录方框的第一行，`#hintLine`。** 位置也是用户定的：「提示的内容不明显，可以直接放在
我们历史记录方框的上面，但是不要把汤面挡住了」。所以它是 `aside.dossier` 的第一个孩子 ——
常驻、能反复读、刷新后还在（正文进 `fengcun.progress.hints`）、整块都在汤面之下。
牌子是「灯芯图标 + 灯语 + 正文」，正文落在 `#hintText` 里（`syncHint()` 是唯一出口，
灯灭就收起来、灯再开自己回来）；紧凑态用 `order: -1` 排在记录条那条横带的第一行。

**提示正文那一格是 `#hintText`，不是 `#hintLine`** —— 写探针、改样式时别拿整条去比文案。

屏幕正中那个浮层（`#hintCenter`）已经删了。它原来负责「点下去当场有反应」，
可 `position: fixed` 居中在手机上正好压着汤面。现在的即时反馈是**那一行自己亮一记**
（`.hint-line.lit` → `@keyframes hintLit`，1.4s）：反馈落在提示该在的地方，不浮到别处去盖东西。
`litHint()` 先摘类再强制回流，所以连点两次求灯第二次也会亮。画廊态右上角还有一件
`.hint` 小 toast 写着「灯来了」，那只是状态提示，不是提示正文的出口 —— 紧凑态它本来就是
`display: none`。

## 提示必须满足三件事

缺一件就算坏。这三条都踩过，`tools/hint-check.mjs` 逐条钉着。

**看得见，而且不压汤面。** 手机上几乎都落紧凑态，而紧凑态里 `.hint-line`（常驻那行）和
`.hint`（飘飘的金字 toast）**都曾经是 `display: none`** —— 两个出口同时堵上，点求灯屏幕上
什么都不会出现，而「孤灯」已经扣掉了。现在 `.hint-line` 是紧凑态记录条那条横带的第一行
（`flex: 1 0 100%` + `order: -1`），常驻可回看。它还不许压汤面、不许压输入条（两个探针都按
矩形相交判定），多出来的高度由 `.frame-window` 的 `margin-top: auto` 与 `.read` 的
`margin-bottom: auto` 对分吸收，画卷高度必须纹丝不动。

**存得住。** `hintedSet` 只记「求过」，`hintMap` 记「灯上写了什么」，两个都进
`fengcun.progress`。只存前者的话，刷新一次提示正文就没了 —— 玩家赔了孤灯，却再也读不到
那句提示。

**不重复。** 客户端把已有提示当 `prev` 一起发上去，服务端据此换到「下一个还没点亮的方向」，
并在 prompt 里要求换角度。否则连点两次求灯会拿到近乎同一句话（旧版固定指 `missing[0]`，
温度 0.4 下措辞也差不多）。

## 模型链，别写死一个

`functions/api/[[path]].js` 的 `HINT_MODELS` 是一条**链**，第一个是主力，出错、抠不出正文、
或者撞泄底闸就依次往下退：

```
@cf/meta/llama-3.3-70b-instruct-fp8-fast      主力
@cf/meta/llama-3.1-8b-instruct-fp8            备胎一
@cf/mistralai/mistral-small-3.1-24b-instruct  备胎二
```

**为什么必须是链**：2026-09-20 发现线上求灯永远只回那句通用兜底。根因是当时的主力
`@cf/meta/llama-3.1-8b-instruct` 早在 5 月 30 号就下线了，binding 报 `5028` ——
而表现只是「提示不换花样」，`/api/health` 里 `hint` 还照样是 `true`，因为绑定确实在。

所以 `/api/hint` 的响应里会带 `model`（这次真正出正文的那个）和 `shape`（一个都没出正文时
的诊断字符串）。**别把模型名写死一个，也别删这两个字段。**

选型是量出来的（同一段 prompt 跑四个汤）：

| 模型 | 耗时 | 神经元/次 | 免费额度≈可点次数 | 结论 |
|---|---|---|---|---|
| `llama-3.3-70b-instruct-fp8-fast` | 1.2–1.7s | 9.86 | ~1014 次/天 | 每次都出正文，中文最稳，从没超 40 字，当主力 |
| `llama-3.1-8b-instruct-fp8` | 1.5–2.1s | 3.77 | ~2651 次/天 | 一次超到 42 字、一次把「同桌」直接写出来 |
| `mistral-small-3.1-24b-instruct` | 1.1–1.5s | 8.88 | ~1127 次/天 | 中文最利落（「她并不是唯一的幸存者。」） |

下面这些别用，都是实测淘汰的：

- `glm-5.3-flash`、`deepseek-v4-flash` → 免费计划直接 403，不是模型坏了是没权限。
- `qwen3-30b-a3b-fp8`、`gpt-oss-20b`、`gemma-4-26b` → 走 binding 回来
  `choices[0].message.content` 是空串。
- `qwq-32b` → 先吐 127 字思考过程；`gemma-4` 有一次 90 秒超时。
- `granite-4.0-h-micro` → 神经元只要 0.74（便宜 13 倍），但会**照抄汤底**
  （「丧尸病毒的传播路径是什么？」），因为它是按指令「提问」而不是「暗示」，跟用法拧着。

顺带一个形状上的坑：不同模型返回结构不一样，而且同一个模型走 REST 和走 binding 还差一层
`result` 外壳（`llama-3.3` / `4-scout` / `mistral` / `granite` 是 OpenAI 风格的
`choices[0].message.content`，`llama-3.1-8b-instruct-fp8` 是老式的 `{response}`）。
`pickAiText()` 四种形状全兜住 —— 只认一种的话，抠出来是空串，线上表现就是这个
「永远回兜底」。

想临时换模型不用改代码：Pages 上设一个 `HINT_MODEL` 变量，它会插到链的最前面。

## 汤底不许漏

system prompt 里那句「绝不写出汤底」挡不住 8B 级小模型，所以两边都补了一道机械闸
`leaks_bottom()`：提示与汤底去空白后出现连续 8 字重合，就弃用该句、退回兜底。

8 是实测取的 —— 正常提示撞满 8 个连续字几乎不可能，而照抄汤底半句必然命中。

## 本地和线上不是同一个进程

本地走 REST（`/ai/run/{model}`）+ wrangler 凭据，线上走 `env.AI` binding，
但**模型链是同一份**，措辞差异属正常。

所以线上求灯能不能用，完全取决于 Pages 项目有没有绑定 Workers AI，而且**绑定变量名必须是
`AI`**。没绑的话 `/api/hint` 不报错，只是每次都回那句兜底。排查办法是部署后打开
`/api/health`，`hint` 是 `false` 就说明 AI 没绑。

## 验收

```bash
node tools/hint-check.mjs http://127.0.0.1:8765/
node tools/finder-hint-check.mjs http://127.0.0.1:8765/
```

前者管「提示看不看得见、是不是排在记录方框第一行、压不压汤面 / 压不压输入条、
刷新后还在不在、加一行会不会挤坏画卷」，后者管「点下去当场亮不亮、
这句话屏幕上是不是只出现在一个地方」。

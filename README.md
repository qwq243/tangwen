# 汤问 · 海龟汤

夜馆画廊。中央金框里是这一卷的汤面，左右两侧墙上的画框露出上一卷 / 下一卷的一角。
底栏打字或按住说话问一句是非；关键点一条条是进度，**把关键点用自己的话讲出来就结案**
（不必复述整个故事），把整个流程讲一遍当然也算。

```bash
cd "D:/00/项目/日常/工具/turtle-soup-demo"
python server.py
```

打开 [http://127.0.0.1:8765/](http://127.0.0.1:8765/)

### 判题档位

掌灯人只会落这几枚印（`server.py` / `functions/api/[[path]].js` 的 `HOST_LABELS`，
前端 `.stamp.*` / `.ledger .a.*` 的配色在 `web/styles.css`）：

| verdict | 印面 | 什么时候落 |
|---|---|---|
| `yes` | 是 | 对照汤底为真（含近义问法） |
| `no` | 不是 | 对照汤底为假 |
| `both` | 是也不是 | 命题分时点 / 分对象 / 分场景成立，两头都咬在汤底上 |
| `partial` | 部分对 | 一句话里有对有错，错的那半只是旁枝 |
| `close` | 接近了 | 摸到关键机制但还没说圆 |
| `irrelevant` | 无关 | 跟故事完全无关（问天气、问主持人本身），答了也对还原汤底没帮助 |
| `unimportant` | 不重要 | 问的确实是故事里的人或事，但材料没写、答对答错都不改汤底 |
| `unanswerable` | 问清楚点 | 压根不是一句能判真假的人话：乱码、半句话、纯情绪 |
| `refuse` | 不能剧透 | 玩家在直接要汤底 |
| `solved` | 结案 | 玩家这一句把汤底说了出来，而且说对了（见下面「结案口径」） |

**结案口径（SOLVE-RULE）：两条路，走通哪条都结案** ——
**(1) 关键点被玩家自己讲出来、讲到够**；**(2) 整段猜中**（他整个流程讲了一遍）。
「关键点**问到**齐」始终不是判据 —— 那是进度。

判据是几个数，两边（`server.py` / `functions/api/[[path]].js`）各有一份同名常量，
`tools/cast-check.py` 的 parity 会逐值比对，`tools/judge-check.py` 也会带上这一道：

| 数 | 值 | 意思 |
|---|---|---|
| `full_guess` | 0.75 | `is_full_guess`：这一句是在**把汤底讲出来**，而不是在问一个点 |
| `guess_correct` | 0.78 | `guess_correct`：讲出来的版本抓住了核心机制 |
| `close_floor` | 0.45 | 「接近了」那一档的下沿：低于这条线就不假装接近 |
| `said_floor` | 0.43 | 单个关键点算「他自己讲出来了」的分线（路 (1) 用） |
| `keys_ratio` | 1.0 | 路 (1) 要讲出**多少比例**的关键点 —— 难度就是这个旋钮 |

`keys_ratio` 是唯一该按「这次想多难」调的：`1.0` = 全都讲出来；`0.75` = 四个里讲出三个
就结案（条数 = `int(键数 × keys_ratio)`，向下取整）。两个分线不是拍脑袋定的，见下面的量法。

路 (1) 与路 (2) 都会把 `bottom` 放出来，落的话不一样（「关键点都说出来了。汤底封卷。」
vs「说对了。汤底封卷。」）。路 (2) 够一条不够另一条时，**不结案**：机制说对了却没被
当成整段汤底讲、或整段讲了但机制没说准，这两种落「接近了」——都要求 `full_guess` 不低于
`close_floor`（探针的 `full_guess` 只有 0.03~0.08，落不进这一档）；差太远才落「是 / 不是」。

**为什么改之一（2026-09-20 用户实报）**：《柜中的孩子》里玩家一路问下来，最后一问把最后一个
关键点问到了，于是当场结案 —— 可他自己并没有想通（连「平行世界」都没往那儿想）。
老口径是 `solved = 所有关键点都问到了`，而关键点是靠**探测性是非题**一条条问出来的：
问齐只说明料凑够了，说没说圆是另一回事。所以把「问到」从判据里拆出去。

**为什么改之二（2026-09-21 上午）**：「无法结束，明明都答出来了」。
这一次是玩家把汤底**完整讲出来**了、末尾顺手带一句「对不对？」，而
`is_full_guess` 那一问当时是拿**语气**判的（「陈述，不是在问」）—— 这一句把
`full_guess` 打到 0.6~0.75 那条线上左右横跳：同一句话连打两次，一次结案一次不结案，
不结案那次落印还是「是」，看着就像游戏没听见他说话。改法：那一问只认**内容**
（有没有把机制讲出来，末尾的求证套话不影响），探针才不算。
实测（`tmp/_wording_ab.py`，14 句 × 2 轮）：改前 3 条不合预期，改后 0 条 ——
讲完整（含各种求证尾巴）0.96~0.97、探针 0.03~0.05、讲歪了 0.07~0.16。
另外把「机制说对了却没结案」单独标出来（`near_miss`）并记一笔 `nearmiss`：
这一档**应当恒为 0**，它涨起来就是结案判据又在拿语气 / 措辞判事 —— 故障灯，不是指标。

**为什么改之三（2026-09-21 下半场，口径对齐）**：用户原话 ——「因为这是一个小游戏，
所以不要求最后用户复述整个故事。难度可以不要太大：如果几个关键点都讲出来了就结案，
如果判断用户已经猜出整个流程也结案。」于是补上路 (1)：多了一组 `said_<关键点>`
问句（「这一句里有没有**他自己**把这一点讲出来」），逐条累积（客户端像 `unlocked`
一样把 `stated` 带回服务端），讲够了就结案 —— 他用自己的话讲出来就算，不必串成一段。

`said_floor` 那个数是量出来的，不是拍的：**真话最低 0.47**（「世界交错了一次」这种
间接说法）、**杂音最高 0.39**（「我是他妈妈吗」这种纯问句擦上来的那一下），取中点 0.43。
量法见 `tmp/_said_wording_ab2.py`（各 4 轮）与累积流程实跑。问句里那句
「**只勾这句话真正讲到的那一条**」也不是修辞：不加它的时候「我那次不算普通流产，
是胎儿跑到另一个世界去了」会被顺带给「我是他妈妈」也打 0.62~0.66 —— 跟真话同档，
杂音顶穿真话，**靠调分线根本分不开**。加了它之后杂音掉到 0.27~0.39、真话还站在 0.47 以上。
所以：**动 `said_` 的问句就要重量这两个边界，别只改一个数。**

界面/前端跟着改的地方（改口径时要一起看）：
- chips 现在有两档：`.key-chip.on` = 他**问到**了；再加 `.said`（右上角一枚小「说」）= 他**自己讲出来**了 ——
  结案看的是后者，所以这一排就是「离结案还有多远」的读数；
- 他自己讲出一个关键点时弹一次揭示牌（kicker「讲 出 来 了」、计数「已讲出 x / y」）；
- 关键点问到齐但还没讲出来时，牌子和 chips 末尾那枚改成「把关键点讲出来 / 讲出来就结案」；
- 求灯带的方向用的是 `unlocked ∪ stated`（他刚说过的点不该再被提示）；
- 入馆引导第四卡与首页简介同一口径（`web/index.html` 的 `tour-card` 肆）。

**验收**：`python tools/judge-check.py` —— 不联网，把 `typesafe` 换成一个照剧本回话的桩，
直接喂判题输出，逐条断言「问齐不结案 / 整段讲对了才结案 / **关键点自己讲出来也结案** /
**问齐但只讲出一个不结案** / **跨轮累积（stated 带回来）能结案** / 讲歪了接近了 / 差太远不是 /
机制说对了没讲成整段 → 接近了并标 `near_miss` / 探针顶不穿这一档 / 直要汤底不能剧透 /
阈值压线与差一线 / 没结案就不许把 bottom 带出去」。它同时跑一遍双链路 parity
（说明正文 + 五个阈值 + `solved` 的两条路 + `said_` 问句 + 「讲对了没结案」那一档的判定与记账
+ state 字段顺序）。`--live` 那一段打真接口，最后两条专盯「讲完整 + 求证尾巴」这一类，
而且**各打两轮** —— 那个故障本来就是抖出来的（同一句话这次结案、下次不结案），单轮过不算过。
界面那一档（chips 的「说」+ 揭示牌计数）钉在 `tools/effect-shot.mjs` 的第 1b 节。

**「是也不是」为什么要单独成档**：题目复杂时，一问的答案本来就可能是「一半是、一半不是」
（例如汤底里这个人死过一次又活着回来，问「他死了吗」答「是」答「不是」都是错的）。
旧版 `pick_host` 是 `yes_p + no_p >= 0.45` 就直接取大的那个，正好把这种题判成错的那一半。
现在 `both` 的概率够高、且 yes / no 也都不低时，先认 `both`（见 `pick_host` 的注释）。
「是也不是」在关键点判定里和 `yes` / `no` 同等对待 —— 题目本来就只有一半是「是」。

**「材料没写」不是「问清楚点」**：`unanswerable` 这一档印出来的字是「问清楚点」，
意思是**怪玩家没说清**，不是「这题我答不上来」。但模型读到「汤底和 facts 里都没写这件事」
时，给的正是 `unanswerable` 的最高分 —— 实测「跳楼的地点是办公楼吗」旧口径下是
`unanswerable .51 / unimportant .43`，落印成了「问清楚点」，等于让一个问法完全清楚的
玩家替模型的为难背锅。两头都改了：`criteria` 里写明「材料里没写不是这一项」，
`pick_host` / `pickHost` 再加一道软档回收 —— 模型自己选了 `unanswerable`（或回了个
档位外的词）时，只要「不重要 / 无关」里有一个够重（`SOFT_RESCUE_MIN`）且追得上
`unanswerable` 的六成（`SOFT_RESCUE_RATIO`），就落那个软档。两条线都是照 `jev-latest`
在这类题上的实测分布量的（`tmp/_vague.py` 是那次的探针，`tmp/_verdict.py` 是离线用例）。
乱码、半句话照旧落「问清楚点」，没有被回收。

改这一组档位要同时动四处：`HOST_LABELS`、`BASE_QUESTIONS.host_answer.criteria`、
`pick_host`、以及 `web/styles.css` 里的 `.stamp.*` / `.ledger .a.*`。
`tools/effect-shot.mjs` 开头有一张 `VERDICTS` 表会挨个喂一遍，漏了哪一档会直接报出来。

**身份类问题先看人物表（`cast`），不许靠汤底代词猜。** 「爱人是男的吗」这种问题以前
没有任何 ground truth 可查：state 里只有事件（`facts`）和隐喻（`metaphor_map`），
「谁是谁、是男是女、什么关系」一直是空的 —— 44 卷里 37 卷的 `facts` 连一条身份断言都没有。
实测《怀孕》那卷：`爱人是男的吗` → `unimportant .65 / yes .23`，`ta 是男的吗` 同一问
连打三次在「是」与「不重要」之间跳，问「是女的吗」也回「不重要」—— 两个方向都是软档，
玩家问不出任何东西。这就是「爱人是男是女分不出来，一会男一会不是」。

改法分两层：

- **数据**：`puzzles.json` 每卷多一张 `cast`（谁是谁、性别、一句话身份），由
  `tools/cast.py` 管。写表口径是**只认材料写明的**：汤底有性别名词（妻子 / 哥哥 / 儿子…）
  或干净的第三人称代词（他 / 她，「其他」不算）才写「男 / 女」，而且每条都要留一句原文
  当证据 —— 脚本会验它是正文的子串，写不出证据就只能写「未写明」。材料真没写的那一档
  不是缺陷：玩家问到就明说「不重要」，别让他反复试。现在 44 卷 / 145 条：写明 97、
  未写明 45、跨阶段 3（双性人、换身体、女与小孩）。
- **口径**：`BASE_QUESTIONS.host_answer` 多一条 `identity` 说明 —— 身份题先看 `cast`，
  写明了的按它判真假，**玩家把性别问反了落「不是」，不许落「不重要」**；汤面用
  ta / 爱人 / 朋友 / 同学 / 有人 这类中性称呼不等于材料没写（那是汤面故意藏的说法）；
  `cast` 标「未写明」、或 `cast` 里根本没这个属性，才落软档；同一个人物的身份在一局里
  固定，正反两个方向的问法必须一是一否，也不许跟 `recent_history` 里落过的印打架。

**`cast` 要排在 state 的最后一位。** 这不是排版洁癖：《怀孕》的「怀孕的是爱人吗」在
「`cast` 放在 `facts` 后面」时稳定答「是」（yes .52–.58），放到末尾后稳定答「不是」
（no .63–.73）—— 交错 4 轮、4:4，`tmp/_order_ab.py` 是那次 A/B。身份题两种顺序都满分
（18/18），所以按事件题那半边定了末尾。**改顺序要连两边一起改**（`server.py` 的 `judge()`
与 `functions/api/[[path]].js` 的同名函数），`tools/cast-check.py` 开头有一道不联网的
断言会比对两边的说明正文与字段顺序，只改一边它直接报红。

**「指认」和「真假」也要分开**：中文里这两种问法长得几乎一样，但期望的印面正好相反 ——
「怀孕的是爱人吗」「怀孕的那个是 ta 吗」问的是**人是谁**，落指认：指的是那个人就答「是」，
哪怕汤面那句话是假的（「爱人」就是汤面里怀孕的那个）；「爱人怀孕了吗」「他在唱歌吗」
问的是**那件事成不成立**，落真假：汤面是假象就答「不是」。没写这条之前，
《怀孕》的这两个问法在同一次会话里会给出互相矛盾的印。`identity` 那段里有这条规则，
`tools/cast-check.py` 的 `LAYER_CASES` 钉了 13 条这样的问法。

**验收**：`python tools/cast-check.py`，全库 303 问 —— 写定的 194 问一是一否、
未写明的 90 问都落「不重要」、3 个跨阶段条目（双性人 / 手术改造 / 童谣里的女人和小孩）
另写 6 条显式用例、5 卷 13 条指认 / 真假分层用例。想看「只有说明、没有人物表」会怎样，跑
`python tools/cast-check.py --no-cast --quick`：同一批问题落错 13/76，错的清一色是
「该判真假却答不重要」。改身份这条要动三处：`tools/cast.py` 的 `CAST` 表、
`tools/cast-check.py` 的期望、以及两边判题说明里的 `identity`。

### 求灯（AI 提示）

左下角的灯默认关。开了之后**底栏（输入条那一行）多出一枚「求灯」**，点一次要一句提示，
代价是这一卷的结案不挂「孤灯」勋章（`used_hint` 会写进排行榜）。

**求灯按钮为什么在底栏**：2026-09-20 之前它在「询问记录」面板里当一行（虚线框、宽度 100%），
夹在记录和提示行之间 —— 用户的原话是「不要在方框里面，用户注意不到」。
现在这枚灯牌（小灯泡 + 求灯两个字）排在 `[输入条 问] [求灯] [麦克风]` 的中间一列：
不在任何方框里，玩家正要提问时视线正好落在这一行。**底栏是三列 grid，求灯那列是 `auto`**，
灯灭时它 `hidden`、整列自己塌成 0，所以开关灯不会让输入条跳一下；
底栏的高度本来就由麦克风定（横版 56 / 竖版 48 / 紧凑 46），40px 的灯牌顶不高它 ——
`compact-scan` 量的六段高度与 `mobile-check` 量的段间重叠因此都不受影响。
加新东西进底栏前先读这一句：**别把这一行撑高。**

**灯语（求来的那句提示）落在哪儿：记录方框的第一行，`#hintLine`。**
位置也是用户定的（同一次实报）：「提示的内容不明显，可以直接放在我们历史记录方框的上面，
但是不要把汤面挡住了」。所以它是 `aside.dossier` 的第一个孩子 ——
常驻、能反复读、刷新后还在（正文进 `fengcun.progress.hints`）、整块都在汤面之下。
牌子是 `灯芯图标 + 「灯语」 + 正文`，正文落在 `#hintText` 里（`syncHint()` 是唯一出口，
灯灭就收起来、灯再开自己回来）；紧凑态用 `order: -1` 排在记录条那条横带的第一行。
**提示正文那一格是 `#hintText`，不是 `#hintLine`** —— 写探针、改样式时别拿整条去比文案。

**那件屏幕正中的浮层（`#hintCenter`）已经删了。** 它原来负责「点下去当场有反应」，
可 `position: fixed` 居中在手机上正好压着汤面 —— 正是用户说的那件「挡住汤面」。
现在的即时反馈是**那一行自己亮一记**（`.hint-line.lit` → `@keyframes hintLit`，1.4s）：
反馈落在提示该在的地方，不浮到别处去盖东西。`litHint()` 先摘类再强制回流，
所以连点两次求灯第二次也会亮。`.hint` 那个小 toast（画廊态右上角，写着「灯来了」）照旧，
但它只是状态提示，不是提示正文的出口 —— 紧凑态它本来就是 `display: none`。

改这一块之后要跑：`node tools/hint-check.mjs`（提示看不看得见、**在不在记录方框第一行、
压不压汤面 / 压不压输入条**、刷新后还在不在、加一行会不会挤坏画卷）与
`node tools/finder-hint-check.mjs`（点下去当场亮不亮、这句话屏幕上是不是只出现在一个地方）。


**项目里有两条各自独立的 AI 链路，别搞混** —— 它们跑在不同的后端上，
而且只有第一条是「必须保证」的：

| 干什么 | 本地 `server.py` | 线上 `functions/api/[[path]].js` | `/api/health` 字段 |
|---|---|---|---|
| **判题（`/api/ask`）** | **TypeSafe `systemone` + `TYPESAFE_MODEL`（`jev-latest`）** | 同左（Pages Secret `TYPESAFE_API_KEY`） | `judge_model` |
| **求灯（`/api/hint`）** | **Workers AI REST，模型链见下** | **Workers AI `env.AI` binding，同一条链** | `hint` / `hint_model` |

**判题那条不许换、不许退。** `model: "jev-latest"` 写死在两边的常量里
（`server.py` 的 `TYPESAFE_MODEL`、`functions/api/[[path]].js` 的 `JUDGE_MODEL`），
没有环境变量入口、也没有备胎模型 —— 因为十档印的准头全在这一颗模型上：
`pick_host` / `pickHost` 里那几条阈值（`both >= 0.3`、`min(yes,no) >= 0.18`、
`yes+no >= 0.45` …）都是照着它的概率分布量的。换模型等于换一套判题口径，
阈值全部作废，而且症状是「偶尔判错」这种最难查的。想换模型就必须连阈值一起重新量。

**除了判题，别的模型调用一律走 Cloudflare Workers AI 的免费额度。**
2026-09-20 把最后一条例外也拆了 —— `/api/refine`（听写润色，走 `CHAT_API_KEY` +
一个自带网关的第三方对话模型）已删，两边各留一个 410 墓碑（和 `/api/stt` 一个规矩），
所以 `health` 里的 `chat` 字段也没了。**要再加模型，只能加进 `HINT_MODELS`，
而且必须是 Workers AI 免费额度里的模型。**

所以线上求灯能不能用，**完全取决于 Pages 项目有没有绑定 Workers AI（绑定变量名必须是 `AI`）**。
没绑的话 `/api/hint` 不报错，只是每次都回同一句兜底：

> 对照汤面里最不对劲的那一句，问它是不是字面意思。

排查办法：部署后打开 `/api/health`，`hint` 是 `false` 就说明 AI 没绑。
本地和线上的提示不是同一个进程跑的（本地走 REST + wrangler 凭据，线上走 binding），
但**模型链是同一份**，措辞差异属正常。

#### 线上求灯的模型链（别写死一个）

`functions/api/[[path]].js` 的 `HINT_MODELS` 是一条**链**，第一个是主力，
出错 / 抠不出正文 / 撞泄底闸就依次往下退。当前：

```
@cf/meta/llama-3.3-70b-instruct-fp8-fast    主力
@cf/meta/llama-3.1-8b-instruct-fp8          备胎一
@cf/mistralai/mistral-small-3.1-24b-instruct 备胎二
```

**为什么必须是链**：2026-09-20 发现线上求灯永远只回那句通用兜底。根因是主力模型
`@cf/meta/llama-3.1-8b-instruct` **早在 5 月 30 号就下线了**，binding 报 `5028` ——
而表现只是「提示不换花样」，`/api/health` 里 `hint` 还照样是 `true`，因为绑定确实在。
所以现在 `/api/hint` 的响应里会带 `model`（这次真正出正文的那个）和 `shape`
（一个都没出正文时的诊断字符串）。**别把模型名写死一个，也别删这两个字段。**

选型是量出来的（`tmp/_o_aisweep.txt`、`tmp/_o_ainurons.txt`，同一段 prompt 跑 4 个汤）：

| 模型 | 耗时 | 神经元/次 | 免费额度≈可点次数 | 结论 |
|---|---|---|---|---|
| `llama-3.3-70b-instruct-fp8-fast` | 1.2–1.7s | 9.86 | ~1014 次/天 | 每次都出正文，中文最稳，从没超 40 字 → **主力** |
| `llama-3.1-8b-instruct-fp8` | 1.5–2.1s | 3.77 | ~2651 次/天 | 一次超到 42 字、一次把「同桌」直接写出来 |
| `mistral-small-3.1-24b-instruct` | 1.1–1.5s | 8.88 | ~1127 次/天 | 中文最利落（「她并不是唯一的幸存者。」） |

下面这些**别用**，都是实测淘汰的：

- `glm-5.3-flash` / `deepseek-v4-flash` → 免费计划直接 403，不是模型坏了是没权限；
- `qwen3-30b-a3b-fp8` / `gpt-oss-20b` / `gemma-4-26b` → 走 binding 回来 `choices[0].message.content` 是空串；
- `qwq-32b` → 先吐 127 字思考过程；`gemma-4` 有一次 90 秒超时；
- `granite-4.0-h-micro` → 神经元只要 0.74（便宜 13 倍），但会**照抄汤底**
  （「丧尸病毒的传播路径是什么？」），因为它是按指令「提问」而不是「暗示」，跟我们的用法拧着。

顺带一个形状上的坑：不同模型返回结构**不一样**，而且同一个模型走 REST 和走 binding
还差一层 `result` 外壳（`llama-3.3/4-scout/mistral/granite` 是 OpenAI 风格的
`choices[0].message.content`，`llama-3.1-8b-instruct-fp8` 是老式的 `{response}`）。
`pickAiText()` 四种形状全兜住 —— 只认一种的话，抠出来是空串，
线上表现就是这个「永远回兜底」。想临时换模型不用改代码：Pages 上设一个
`HINT_MODEL` 变量，它会插到链的最前面。

**提示只在一个地方：记录方框的第一行 `.hint-line`**（位置是用户定的，见上面那一节）。
2026-09-20 之前它有三个出口，其中 `#hintCenter`（屏幕正中浮一次再渐隐）已经删掉 ——
它在手机上正好压着汤面，正是用户说的「挡住汤面」。点求灯的即时反馈现在由那一行自己给
（`.hint-line.lit`）。画廊态还有一件 `.hint` 小 toast（写着「灯来了」），
那只是状态提示，不是提示正文的出口。

**提示必须满足三件事，缺一件就算坏**（都踩过，`tools/hint-check.mjs` 逐条钉）：

1. **看得见，而且不压汤面。** 手机上几乎都落紧凑态，而紧凑态里 `.hint-line`（常驻那行）和
   `.hint`（飘飘的金字 toast）**都曾经是 `display: none`** ——
   两个出口同时堵上，点求灯屏幕上什么都不会出现，而「孤灯」已经扣掉了。
   现在 `.hint-line` 是紧凑态记录条那条横带的**第一行**（`flex: 1 0 100%` + `order: -1`），
   常驻可回看；`.hint` toast 仍然只在画廊态有位置。
   **它还不许压汤面、不许压输入条**（两个探针都按矩形相交判定），
   多出来的高度由 `.frame-window` 的 `margin-top:auto` 与 `.read` 的 `margin-bottom:auto`
   对分吸收 —— 画卷高度必须纹丝不动。**加新的提示出口前先想清楚在紧凑态落在哪，
   以及会不会盖在汤面上。**
2. **存得住。** `hintedSet` 只记「求过」，`hintMap` 记「灯上写了什么」，
   两个都进 `fengcun.progress`。只存前者的话，刷新一次提示正文就没了 ——
   玩家赔了孤灯，却再也读不到那句提示。
3. **不重复。** 客户端把已有提示当 `prev` 一起发上去，服务端据此换到「下一个还没点亮的方向」
   并在 prompt 里要求换角度。否则连点两次求灯会拿到近乎同一句话
   （旧版固定指 `missing[0]`，温度 0.4 下措辞也差不多）。

**汤底不许漏。** system prompt 里那句「绝不写出汤底」挡不住 8B 级小模型，
所以两边都补了一道机械闸 `leaks_bottom()`：提示与汤底去空白后出现连续 8 字重合就弃用该句、退回兜底。
8 是实测取的 —— 正常提示撞满 8 个连续字几乎不可能，而照抄汤底半句必然命中。

### 埋点与每日统计

前端只记「什么事件发生了几次」，**不记问题原文、不记 IP、不记 UA、不记设备**。

事件七种：`pv`（开卷成功）、`ask`、`hint`、`solve`、`give`，以及 2026-09-20 为「模型调用」
加的两档 `judgefail`（判题调用失败）、`hintfallback`（求灯退到兜底）。
按模型的求灯次数不进事件表，它是当天的一张小字典（`day.m`，见上面「模型调用怎么记的」）。
**但事件不在同一个地方记**：

| 事件 | 谁记的 | 记在哪 |
|---|---|---|
| `pv` | 客户端 | `web/app.js` 的 `track()`，攒批走 `/api/track` |
| `ask` `hint` `solve` `give` `judgefail` `hintfallback` 与 `day.m` | **服务端** | 各自接口里自己数：`server.py` 的 `bump_track()` / Worker 的 `bumpTrack()` |

**为什么这几档改成服务端数**：2026-09-20 用户报「后台好像不能正常更新，提问之类的没记录」——
那几档原本写在客户端，而线上跑着的是**旧的 `app.js`**（页面改动要等下一次部署才生效），
于是后台的提问/求灯/结案整天是 0，访问量却照常涨（实况 `pv=67 uv=22 ask=0`），
看着像后台坏了。判题、求灯、放弃这些**服务端本来就知道**的事，不该由页面转述。
`tools/track-check.mjs` 钉住这条（还顺便钉住「两边都记就是记双」）。

**「模型调用」那两档走的是同一条路**：它们也只有服务端知道（判题挂了、模型链退到头了），
而且**必须跟主计数并进同一次 KV 写**（`bumpTrack` 传 `model` 参数那一路）——
为了多记一个数再读-改-写一次 KV，免费额度是按写次数算的，不值。

**以后加新事件先问一句：服务端自己看得见吗？** 看得见就写进接口（`bump_track` / `bumpTrack`），
看不见才写客户端（比如「这一卷在浏览器里真的开出来了」只有页面知道）。

客户端那一档（`pv`）是**攒批发**：攒够 20 秒、或者页面要走了（`pagehide` / 切到后台）才
POST 一次 `/api/track`，一次会话通常只写 1~3 次 KV —— 一条事件发一次请求的话，
云那边一天几千次 KV 写直接顶到免费额度。

**页面要走了那一次必须走 `navigator.sendBeacon`**：普通 `fetch` 在这个时机会被浏览器
直接掐掉，而结案恰好是「看完就走」的场景，会整批丢光。

服务端按 **Asia/Shanghai** 切日聚合进已有的 KV 命名空间（绑定名 `BOARD`）：

| 键 | 内容 | 说明 |
|---|---|---|
| `st:d:YYYY-MM-DD` | `{"c":{pv,uv,new,ask,hint,solve,give},"p":{"<卷id>":{ask,hint,solve}}}` | 当日计数 + 分卷明细 |
| `st:u:YYYY-MM-DD` | `["<uid>", ...]` | 当日出现过的 uid，只用于 UV 去重，60 天自清，单键最多留 3000 个 |
| `st:f:<uid>` | `"YYYY-MM-DD"` | 该 uid 首次出现日，用来算「新增」 |

日期一定要按 +8 切：Worker 跑在 UTC，直接取 UTC 日期的话，北京时间 00:00–08:00
的访问会记到前一天去，国内站点这是肉眼可见的错。

uid 就是排行榜那个 `player.id`（浏览器本地随机生成），跟人没有对应关系；
`st:f:` 里也只留「这串随机数第一次来是哪天」。

**已知偏差，别当精确账**：日计数是「读-改-写」，同一天的请求并发撞在一起时会少记几笔；
KV 本身也是最终一致（跨机房最长 60 秒）。看趋势够用。

**服务端自己数那四档的代价**：每问一次多一对 KV 读+写（原先一整个会话才写 1~3 次）。
这个量级跟「每问一次就要调一次判题模型」比可以忽略 —— 出得起模型调用，就出得起这一笔。
反过来才是要防的：判题失败（模型挂了 / 超时）**也照样记这一问**，不然上游一挂，
后台看起来就是「今天没人提问」。`tools/admin-check.py` 有一条用例专门钉这个。

### 后台（账房）

地址 `/admin/`。零依赖单页，图是手写 SVG（为三条折线引一整个图表库不划算）。
页面**不从任何地方链过去**，地址记在这儿就行 —— 真正的门是密钥。

- **登录**：Pages 项目的 production Secret `ADMIN_KEY`（43 字符随机串，不在代码里、
  不进仓库、不进包）。`POST /api/admin/login` 常数时间比对；成功后发一个
  **HMAC-SHA256 签名的自包含 token**，有效期 12 小时 —— payload 里只有过期时间戳，
  服务端不存会话表，也就没有会话要清理。token 放 `sessionStorage`，关标签页即失效。
- **限流**：同一 IP 15 分钟内连错 8 次锁死。锁住期间**对的密钥也进不去**，防爆破优先。
- **会自己转**：进来之后每 30 秒拉一次统计（只拉统计，不重画卷宗那份 44 条 `<details>` ——
  重画会把展开的收回去、把滚动位置顶掉，而它本来就随包发布、不会变）。切到别的标签页就停，
  切回来立刻补一次。以前只有「进页面」和「点刷新」两个时刻会取数，玩家提问之后不点一下，
  看到的就是几分钟前的数，很容易误判成「后台没在记」。
- **能看**：近 7/14/30/90 天趋势与汇总、分卷明细、近 7 日逐日、**模型调用**（见下）、
  44 卷汤底与关键点核对（每卷那行挂着卷 id、**汤色**、难度、关键点数四枚签 ——
  汤色要在这儿一眼扫得出哪几卷是黑汤，后台本来就是核对分类的地方）、导出 JSON。
  **能改**：排行榜删单条 / 清空本卷。
- **卷宗核对能搜能筛**（2026-09-20 加）：顶上一条搜索框 + 一排分类 chip
  （全部 / 清汤 / 红汤 / 黑汤 ｜ 浅 / 中 / 深，各带全库卷数）。搜索覆盖**整卷正文** ——
  卷名、卷号（`id`）、汤面、汤底、关键点的标题与问法，空格分开的多个词是「都要命中」（AND）。
  两类分类是并列的，能叠（「黑汤 + 深」）。卷尾计数写成 `N / 44 卷`，
  但**卷号仍是全库里的号**（筛出「第 07 卷」跟在卷面上看到的是同一个 07）——
  核对时说的卷号不能跟着筛选漂。
  只搜标题是不够的：核对的场景常常是「我记得有个词，在哪一卷来着」，那个词多半在汤底里。
- **模型调用卡**（2026-09-20 加，2026-09-21 补一格）：五格 —— 判题调用 / 判题失败 /
  讲对了没结案 / 求灯调用 / 求灯兜底（各带今日与区间合计，失败、兜底、讲对了没结案
  不为 0 时标红），下面一张表按模型分解求灯次数与占比。

**模型调用怎么记的**（口径，改它要连 `server.py` 的 `bump_track` 与 Worker 的同名函数一起改）：

| 数 | 怎么来的 | 它出问题长什么样 |
|---|---|---|
| `ask`（提问） | 每次通过校验的 `/api/ask` 一笔 | —— |
| `judgefail` | 判题调用抛错（HTTPError / 超时 / 其它）各一笔 | 问什么都答不上来，而「提问」照涨 |
| `hint`（求灯） | 每次成功的 `/api/hint` 一笔 | —— |
| `day.m[模型]` | 求灯这一句**实际是谁答的**（`make_hint` 的第二个回值） | 主力模型下线时，表里只剩备胎那行 |
| `hintfallback` | `model` 是空串（AI 没绑 / 模型链全挂 / 撞泄底闸退到头） | 「求灯永远同一句话」，以前后台一点痕迹都没有 |
| `nearmiss` | 机制说对了（`guess_correct` 够线）却没被当成整段汤底讲（`full_guess` 不够线），于是没结案 | **这一档应当恒为 0**：涨起来就是结案判据又在拿语气 / 措辞判事（2026-09-21 那一报的形状），玩家看到的是「我都答出来了它却不结案」 |

**判题那条不按模型记**：模型是写死的 `jev-latest`（十档阈值照它量的，不许换），
而且每次提问必发一次调用 —— 所以「判题调用次数」就等于提问数，多记一笔是重复计。
它和 `judgefail` 的差就是「模型调用没回来」的那些，这一层信息已经够了。
`stats` 响应里另带 `judge_model`，卡片把它摆出来核对（换模型是静默故障）。


后台自己的两处硬约束（都在 `tools/admin-shot.mjs` 里钉着）：

1. **图不能被缩放**：`viewBox` 必须按容器**实测像素宽度**画（`viewBox="0 0 W H"` 且
   `W == 渲染宽度`）。早先写法是 viewBox 钉死 1000 宽再让 SVG 整体缩放，
   390 宽的手机上 12px 的刻度被缩成 3.7px —— 等于没有刻度。窗口尺寸变了要重画（防抖 160ms）。
2. **卷宗要先于统计取**：`loadAll()` 里 `await loadVolumes()` 再 `await loadStats()`，串行。
   并行的话统计先回来、卷宗还是空的，排行榜下拉和表就一直是白的，而没人会再触发一次填充。

### 搜剧本

44 卷顺着滑太慢，顶上给一条搜索（`#finder`）。索引四样：**卷名、卷号（`02` 和 `2` 都认）、
汤面正文、汤色**（敲「黑汤」就把这一类列出来），命中按「卷名 → 卷号 → 正文 → 汤色」排，
同档按卷序；已结案的挂一枚「已结案」，正停着的那一卷卷名标金。
点结果直接落卷（不走推拉动画 —— 搜索是「翻到第几卷」，不是「顺着往下翻」）。

**点一下搜索框（或放大镜那枚图标），面板连着下面两行分类就出来** —— 不必先敲一个字。
`app.js` 里分两个动作：`revealFind()` 只把面板露出来、不动输入框里的字（点进来看看
有什么可挑的），`openFind()` 是「重新搜一次」、会清空输入框（按 `K` 与点放大镜走这条）。
一处要留神：**揭了就得 `renderFind()`** —— 少了这一步会留下「`findOn` 为真但列表收着」
的死状态，之后 `openFind()` 因为 `if (findOn) return` 直接返回，放大镜怎么点都打不开
（紧凑态实测踩过，`tools/finder-hint-check.mjs` 第 6 段钉着）。

面板的**第一行是汤色筛选**（`li.ftags`，sticky）：全部 / 清汤 / 红汤 / 黑汤，各带卷数。

- **它为什么住在 `#findList` 里面**：这样它跟列表同框、同一块滚动区，不用另算一块
  绝对定位的高度，也就不动 `.finder` 自身的高度 —— 而「`.finder` 高 34px、落在顶部一条带里、
  不压画卷」正是 `tools/finder-timer-check.mjs` 的 A1 三条断言量的东西。代价是 `#findList`
  里除了结果行还住着两个不是结果的 `li`（`li.ftags` 和空态 `li.empty`），
  **取结果行一律用 `li[data-i]`**，别写 `#findList li`。
- **不敲字就是「翻这一类」**：`findHits("")` 返回整类、且**不吃 `FIND_MAX` 的 24 条截断**
  （敲了字那是「搜」，截断才有意义）。所以按 `K` 打开时亮着「全部」、下面列的就是全部 44 卷。
- **「筛选过再搜」的空态要说清是哪一层空的**：`「清汤」里没有「圣诞」`，不是「没有这一卷」。

两种形态、**一份 DOM**，靠 CSS 切（`app.js` 的 `openFind/closeFind` 只管加不加 `.finding`）：

| | 摆在哪 | 长什么样 |
|---|---|---|
| 横版 / 竖版画廊 | `.finder` 绝对定位在顶墙中央（横版 `top: 3.2%`、竖版 `top: 3vw; width: 62vw`） | 输入条常驻，敲字或按 `K` 出面板 |
| 紧凑态 | 顶栏图标群最左（`right: 168px`） | 只留一枚放大镜，点开整屏浮层（`.stage.compact.finding`），点空白 / Esc 收起 |

紧凑态为什么非得是浮层：顶栏那一行**没有横向余量**再塞一条输入框
（卷号 + 标题 + 换卷 ×2 + 声音 + 灯已经排满），而且 `flex-direction: column` 里同级元素只占一行，
没法把输入框并进那一行。所以 `.plaque` 的右侧留白从 164px 加到 200px 给放大镜腾位，
输入框本体只在浮层里出现。

**浮层用 `position: absolute` 而不是 `fixed`**：`.stage.compact` 自己带 `transform: translateY(--vp-top)`，
`fixed` 在里面会改以它为基准，反而算不准。

快捷键：`K` 打开（宽屏直接聚焦输入框，紧凑态展开浮层），`Esc` 收起。
搜索框里打字**不会**触发 `m`/`h`/`?`/`k` 那些单键快捷键 —— 全局 keydown 里对 `#findInput` 先 return。

**`closeFind()` 不重置汤色筛选**（输入框也不清）：筛着的汤色是一种「正在浏览哪一类」的状态，
再按 `K` 回来时还是那一类才对；两者在面板里都看得见（选中的那枚印是亮的）。
真正清空两样的是「×」，所以它的显隐判据是 `!findInput.value && !findSoup`（`syncFindClear`）——
只要还有一样没清，它就得在，那是唯一的清空出口。

### 难度标签与「几人结案」

**难度**（浅 / 中 / 深）写在 `puzzles.json` 每卷的 `difficulty` 字段里 —— 数据说了算，
代码只负责显示（`tools/difficulty.py` 是算法本身，`python tools/difficulty.py` 只打印分数表）：

    score = 关键点数 × 4 + 隐喻层数 × 2 + 事实条数        ≤31 浅 / 32~37 中 / ≥38 深

权重是按「哪一项真的让人卡住」配的：关键点数是这一卷**要问出几件事**，最硬；
`metaphor_map` 是汤面隐喻翻到汤底事实要绕几道弯；`facts` 是搜索空间的大小。
44 卷实测范围 18~48，两刀切在 31 / 38，三档 17 / 18 / 9 卷，**分数与档位严格单调**
（不会出现「同分不同档」）。觉得哪一卷不该是这个档，直接改那一个字；
`difficulty.py --write` 只补**还没有值**的卷，不会覆盖手改过的（要重算全部得 `--force`）。
**加卷之后记得跑一遍**（`python tools/difficulty.py --write`）—— 它只填缺的那几卷，
新增的卷目自己就补上了难度（2026-09-20 从 34 卷扩到 44 卷时就是这么跟上的）。

它出现在五个地方：**卷面上**（卷号旁边一枚描金小印，跟卷号同一行 —— 竖版从 `.plaque` 的
`top:85vw` 到 `.read` 的 `102vw` 只剩 ~67px，另起一行会压到汤面）、**搜索列表每行**（选卷时一眼看深浅）、
**搜索面板的筛选行**（见下）、**榜头**、**结案画卷**。

**筛选行是「挑一卷合适的」那个入口**：汤色三枚 + 一条细分隔线 + 难度三枚，共用一个「全部」
（点它两道筛选一起清）。点了某一档、输入框是空的，就把那一档整卷列出来
（不受 24 条上限约束 —— 那一档有几卷就列几卷）；敲「浅 / 中 / 深」也能当关键词搜。
`data-diff` 与 `data-soup` 走同一个点击代理（`#findList` 上那一个）。

**为什么不拆成两行**：竖版的 `.finder` 只有 62vw（390 宽的屏上是 242px），
两行会各折成两行、吃掉四条的高度，列表只剩四五条（实测过一版，截图就是那样）。
一行两组折两行就够，而且两组的话本身分得清（清汤/红汤/黑汤 vs 浅/中/深），不用再加小标签。

`tools/solve-check.mjs` 第 6 节钉着这条：只有一行、难度三枚、汤色那四枚还在、默认停在共用的「全部」、
有分隔线、**筛选行真的在屏幕上**（跑之前先关掉排行榜遮罩 —— 否则只是在 DOM 里点得到、屏幕上看不见，
那种「能用」是假的）、点「深」列出的每条都是深卷、条数与 chip 上的数一致、回「全部」是全部卷数。

**「几人结案」不能拿排行榜的行数当** —— 每卷只留前 30 行（按问数、用时排），
第 31 个人结案了行也被挤掉。所以服务端另有一张 `{卷id: 人数}` 表：
本地 `data/solves.json`，线上 KV 的 `solves` 单键（一次读一次写，不是每卷一个键，因为开页面要看全部 44 卷）。
只在「这一卷第一次见到这个 player id」时 +1（player id 是浏览器本地生成的随机串），**同一个人重复结案不重复计人**。

- 接口：`/api/solves` 一次给全部 44 卷的人数（**故意与 `/api/puzzles` 分开**：那份卷宗是启动时算好、
  几十年不变的，还带 60 秒缓存，人数却是每次结案都会变的，混在一起就得每请求重序列化 18KB）；
  `/api/score` 的响应里也带 `solves` 与 `first`（这一份算不算新人）。
- 界面上：搜索列表每行「N 人」（0 人的不显示）、榜头「《卷名》· 浅卷 · N 人已结案」、
  结案画卷里那句「**你是第 N 位结案**」—— 只在 `first` 为真时写（重复结案不谎报名次）。
- **已知偏差，别当精确账**：超过 30 人之后，被挤出前 30 的那位再结一次会被多算一次。
  这个数只是给玩家看的「这一卷有没有人通过」，不是排行榜的账。

### 汤色：清汤 / 红汤 / 黑汤

**难度是「要问出几件事」，汤色是「要咽下什么」—— 两个正交的轴**，所以是两个字段、两枚印。
浅卷可以是黑汤，深卷可以是红汤；挑卷的时候这两件事都得看得见。

**口径的来源**是知乎《海龟汤：一场脑洞大开的推理游戏之旅》第四节的「海龟汤常见分类」
（`https://zhuanlan.zhihu.com/p/2032042332867007256`，作者陶小敬，收录于「桌游与剧本杀」专栏）。
原文就是三条，**每类只有一句定性描述、一个例子都没给，也没说分类维度**：

    清汤：无恐怖、无死亡，轻松脑洞。
    红汤：有尸体、命案，偏悬疑。
    黑汤：重口味、血腥、惊悚，慎玩。

**下面这三条判定是照原文那一句推出来的操作化，不是原文写着的**（原文没写维度，
所以「按什么切」这一步是这里补的，改口径就改这里）：

    清汤  汤底里没有人死 —— 轻松的脑洞、典故
    红汤  有人死（尸体 / 命案 / 亡者 / 灵异），但死法本身不是卖点
    黑汤  重口本身就是卖点 —— 对尸体或身体的处置（分尸、剥皮、食、寄生、
          拼接、活埋、换脑……），无论出没出尸体

44 卷判下来是 **清汤 3 / 红汤 17 / 黑汤 24**。这个分布不是配错的：这一套卷子本来就偏恐怖，
海龟汤几乎卷卷有人死，真正稀罕的是清汤。**想让不玩恐怖的人也能进来，缺的是清汤**，
补卷的时候按这个缺口补。

**为什么不像难度那样纯公式算**：难度那三项（关键点数 / 隐喻层数 / 事实条数）全是现成的数，
一算就准；汤色是语义判断 ——「有没有人死」能从汤底扫出来，「这个死法算不算重口」得读一遍。
所以 `tools/soup.py` 给的是**关键词提议 + 命中证据**，跟 `difficulty.py` 一样守同一条规矩：
**值以 `puzzles.json` 的 `soup` 字段为准**，已有的值不会被覆盖（除非 `--force`）。

关键词表是照着最初的 34 卷量出来的，**新卷看证据列、别只看提议列**。几个已知的粗细
（都在 `soup.py` 的注释里）：`手术` 本来在重口词里，但第 34 卷那台是性别重置手术，
不是重口，所以拿掉了；第 10 卷「出租房」的死亡写成「让他永远待在了天花板里」，
靠自己那句「封进」才认得出来。

从 B 站合集补进 10 卷时又验了一次这张词表，命中两处误判，都在 `puzzles.json` 里
人工定了、脚本照规矩把它们列进「不一致」等人复看：《蚊子》只因为汤底有个「血」字
被提议成黑汤（死的是一只蚊子、血是吸来的，该是清汤）；《日记》的「贴狗皮 / 用尸体
做狗粮」没被认出来（实际是黑汤）。**别为了消掉这两条去扩词表** ——「血」「死」在
别的卷里是有效信号，收紧一点就会误伤。

它出现在四个地方，**颜色只在 `styles.css` 顶上那三行 `[data-soup]` 里定义一次**
（`--sp` / `--sp-bd` / `--sp-bg`，凡是带 `data-soup` 的元素都从那里取）：

| 出口 | 样子 |
|---|---|
| **卷面上** | 卷号旁边第二枚小印（跟难度同一套印样，跟卷号同一行） |
| **搜剧本列表每行** | 第三次列，选卷前就知道这碗是什么汤 |
| **汤色筛选行** | 面板第一行四枚 chip，各带卷数（见上面「搜剧本」） |
| **结案画卷** | 那一行小字里报一句汤色 |

**三色的取法**：清用苔青 `#8fae7a`、红用朱砂 `#c4563c`（都比原色提亮过，深色墙上才读得出来）；
**黑没有写成黑字** —— 夜馆本来就是深底，黑字看不见。改成「墨底 + 朱边」：
底比周围更暗读作黑，朱边就是原文那两个字「慎玩」。

### 计时：手上时间

排行榜上的「用时」不是墙上时间，是**手上时间**：从开这一卷起算，只要**长时间没有任何操作**
（提问 / 打字 / 拖动画框 / 点按钮 / 从别的 App 切回来）就**停表**，下一次操作自动接着走，
暂停的那一段直接丢掉。出门吃个饭、手机息屏、切去聊天再回来，用时不会凭空涨掉几千秒。

- 阈值 `IDLE_MS` 默认 **60 秒**（`app.js`「计时」那一段）。探针要验停表不可能真等一分钟，
  往 `localStorage` 塞 `fengcun.idleMs`（毫秒，≥200）就能改，`tools/finder-timer-check.mjs` 用的就是这个口子。
- 判「有操作」用一组 window 级的 passive 监听（`pointerdown/keydown/wheel/touchstart`），
  所以**任何**点击都算，不用逐个控件挂钩。切走 / 息屏走 `visibilitychange` 立刻停，回来接上。
- 状态只有一台表（同一时刻只在解一卷），换卷时 `startClock` 先把上一卷结清。
- **停表必须看得见，两套布局各有一个出口**（和求灯同一条规矩）：
  画廊态是 `#elapsed` 前面的「∥」+ 变暗，紧凑态 `#elapsed` 是 `display: none`，
  靠 `.meter` 里的 `#pauseTag`「停表」那枚小签兜住。两个标记在 `syncPauseTag()` 里同帧翻，
  不然要等下一次 1s 轮询才看得出变化。
- 累计值存进 `fengcun.progress` 的 `active`（毫秒 / 按卷），和 `history` 一起落盘；
  `pagehide` 会先 `settleClock()` 再存。老存档里那套 `started`（首次开卷时间戳）已经不用了。

#### 结案那一刻要做的三件事（2026-09-20 用户实报「结案了没结算、榜上没有我、还在记时」）

1. **把表摘下**（`stopClock()`），不是暂停。`pauseClock()` 只是暂停，下一次 pointerdown
   （点掉结案画卷那一下就是）会被 `touchClock` 接回去接着走 —— 这就是「还在记时」。
   `stopClock()` 把 `clock.id` 清空；`startClock()` 另外拦一道：`solvedSet` 里的卷不再起表。
   摘表要在 `submitScore()` **之前** —— 成绩里的「用时」读的就是 `elapsedMsOf()`。
2. **停表标记不挂**。结案之后的时间是结清的定量，不是「暂停中」，所以 `#elapsed` 不带「∥」、
   `#pauseTag` 也不出来。两个出口共用同一个判据 `pausedNow()`，别各判一套。
3. **成绩要在推画卷之前交**（`submitScore` 先 await，再 `setTimeout(showFinale, 480)`）——
   画卷里那句「你是第 N 位结案」要用成绩的返回值（`solves` / `first`）。
   网络卡住时给它 2.5 秒上限：超了就先推画卷（少那一句），成绩回来再补写。
4. **排行榜面板要先揭层再取数**。`loadBoard()` 开头有一条「层关着就直接返回」，
   而 `setBoard()` 原来是先调 `loadBoard()` 再揭层 —— 于是**第一次打开排行榜永远是空的**，
   只有「开着面板换卷」（`paintStrip` 里那次）才会填上。用户看到空榜，就以为成绩没结算，
   其实那一行早就写进服务端了。这条由 `tools/solve-check.mjs` 钉住（它同时验服务端那一行）。

### 语音识别：跑在浏览器里

识别走浏览器自带的 **Web Speech API**（`SpeechRecognition` / `webkitSpeechRecognition`）：
按住麦克风说话，识别结果**先落进输入框**，玩家确认或改完再按「问」发送。
服务端不再做听写，`/api/stt` 现在直接回 `410`（留个明确的墓碑，免得旧前端白传音频）。

这样做的取舍：

- 好：零依赖、零上传、边说边出字，服务器不用再扛模型和 CPU。
- 坏：识别在厂商云上做。**Chrome / Edge 走 Google 的服务，大陆网络常常连不上**
  （表现为按下后立刻 `network` 错误）。连不上时页面会明确提示「语音服务连不上，先打字吧」，
  不会让人对着麦克风干等。Firefox 不支持，麦克风按钮会置灰并提示打字。
- 如果以后要脱离网络服务，接回服务端 ASR 只需恢复 `asr.py` 并把 `startVoice()` 里的
  分支换回录音上传，前端其余部分不用动。

### 音效与环境音（`web/audio.js`）

零素材：整段声音都是 Web Audio 现场合成的（低频长音铺底 + 小调五声音阶上的偶发单音），
所以一个字节的音频文件都不下载。三条规矩，改它之前先读：

**一、页面在后台就一声不许出。** 2026-09-20 用户实报「离开页面就不要声音了」。
改之前 `on` 只管用户那个开关，切到别的标签页 / 切到别的 app，长音和偶发单音都照响。
现在三条路都拦：`visibilitychange`→hidden、`pagehide`（关页 / 跳走 / 进 bfcache 都走它）、
`freeze`（Chrome 的页面生命周期）。做法是**淡出之后把整个 AudioContext `suspend()`** ——
不是把音量拧到 0（拧到 0 那些振荡器还在跑，回头一看 CPU 白烧）。

还有个容易漏的点：**后台期间连合成都不许做**，闸门要下在两处（`sfx()` 与排程那一层）。
因为 `suspend()` 之后 `ctx.currentTime` 是**停住的**，这时候排下去的音符全挤在同一瞬间，
切回来会「轰」地一起响 —— 这是把 ctx 挂起而不是静音之后才会出现的坑。
回到前台：开关还开着就 `resume()` + 淡回原音量，排程接着排。

**二、同一件事不许每次都一个样。** 用户的原话是「不要太单调，增加随机性，否则用户会很烦躁」。
两层分开做，别混：

| 层 | 怎么做 | 幅度 |
|---|---|---|
| 形状变体 | `pickVariant(key, [...])`：一件事备 2~3 支写法，选了之后**不连着重复**同一支 | 落印 3 支底子、解锁 3 支、悬停 3 支、滑卷 3 支、结案尾巴 2 支… |
| 参数抖动 | `jit(freq, cents)` / `rnd(lo, hi)`：音高、时值、增益各抖一点 | 音高 ±10~40 音分（100 音分＝半音，再多就「跑调」）、时值 ±10~25% |

第二层是「合成音色听久了发木」的解药：同一支写法连听两次也不完全一样。

**落印是听得最多的一件**（每一次提问都响），所以那里的分化最细：底子三选一（金属 / 木头 / 砂面），
尾巴按 `verdict` 分开 —— 是（轻轻一挑）/ 不是（闷的短叹）/ 是也不是（三全音打架）/
部分对（半步）/ 接近了（往上蹭半音）/ 无关·不重要（一层沙声）/ 问清楚点（两记木叩）/
不能剧透（低而硬的一记）/ 结案（两组走向随机）。以前中间那七档是一模一样的响。

**三、高频音必须节流。** `MIN_GAP` 一张表（悬停 110ms、拖动 95ms、滑卷 180ms…）：
鼠标扫过一排按钮会连着触发 `mouseenter`，拖动画卷每一帧都可能出音 ——
不拦就是「嗒嗒嗒嗒」一梭子，比不响更烦。探针量的是「12 次同步 hover 只落下一声」。

补过一遍「安静的地方」（2026-09-20）：点灯 / 吹灭（`wickOn` / `wickOff`）、灯语落地（`hint`）、
开卷第一声（`open`，跟音乐一起起）、搜剧本开合（`find`）、从搜索结果落卷（`seek`，与滑卷区分）、
停表 / 回表（`pause` / `resume`，极轻）、引导翻页（`tour`）、拖动（`drag`）。
以前这几件事要么没声音，要么借一声鼠标划过代替。

只读诊断两枚（排查与探针用）：`FengcunAudio.state`（AudioContext 的状态）、
`FengcunAudio.playing`（此刻该不该有声音 = 开关开着 + 页面在前台）。

**验收**：`node tools/audio-check.mjs` —— 不往引擎里塞测试开关，而是在页面脚本之前
把 WebAudio 的三个工厂（`createOscillator` / `createBufferSource` / `createBiquadFilter`）
包一层，记下每次合成的「零件」，于是每次出音都有一条签名。两把尺子分开用：
**形状**（用了哪些零件）变了＝变体在工作，**精确签名**变了＝抖动在工作；
静音那几条走真事件（`visibilityState` 用 `defineProperty` 覆盖后派发 `visibilitychange`）。
它顺带钉住「点灯 / 搜索 / 换卷的声音真的接在事件上」（点一下，量到零件才算数）。

### 写界面时的几个硬约束

**展示层级：解锁 < 结案。** 关键点解锁（`.reveal-plate`）是一条「通知」，结案（`.finale`）才是「结论」。
两处字号是刻意分开的，`.reveal-title` 必须小于 `.finale-title`：

| | 横版 | 竖屏 |
|---|---|---|
| `.reveal-title` | `clamp(21px, 2.4vw, 34px)` | `clamp(19px, 5.4vw, 26px)` |
| `.finale-title` | `clamp(30px, 3.8vw, 46px)` | 同左（手机取到 30px） |

竖屏那条 `.stage.tall .reveal-title` 是最容易写崩的地方 —— 它曾经是 `clamp(26px, 8vw, 40px)`，
在 390 宽的屏上算出 31.2px，比结案的 30px 还大，解锁那一下比结案还响。`effect-shot.mjs`
里有一条断言专门钉这件事，改字号后跑一遍。

**`.finale-scroll` 的 `padding-bottom: 136px` 是给朱印留的固定带，不能挪到 `.finale-body` 上。**
汤底最长 248 字，手机上 body 会滚；预留一旦做在内容末尾（`body` 的 padding-bottom），
滚动时它跟着滚出视野，朱印就会压到最后几行正文上。同理 `.finale-scroll` 上不能挂外侧
`box-shadow` —— 展开动画用的是 `clip-path`，会把落在边框盒外的阴影一并裁掉。

**解锁揭示牌 `.reveal-plate` 有 `max-width: min(78%, 620px)`。** 最长关键点标签 7 字，
一次解锁多条时用「 · 」拼起来，没有这个上限会直接顶到屏幕边。

**紧凑态里不许把某个功能的「出口」`display: none` 掉。** 紧凑态是按「屏幕不够高」裁出来的，
裁的应该只是装饰（`.motes` / `.wing` / `.seal` / `.mic-cap` / `.heard`），
凡是「玩家点了按钮要看到东西」的元素都必须留一个出口，而且那个出口得是真能显示的
（别再挂在一个自己也是 `display: none` 的容器上）。
求灯就踩过这个坑：紧凑态把 `.hint-line` 和 `.hint` 同时藏了，
点求灯等于什么都不会发生，而「孤灯」已经扣掉了 —— 出口全堵的功能比没有这个功能更糟。
改紧凑态之前先想清楚：**这个功能的结果，在紧凑态落在屏幕上哪一块？**

**出口还得落在玩家找得到、且不盖住正文的地方。** 同一个功能改两次位置就是这一条：
求灯按钮从记录面板里挪到底栏（用户「注意不到」），提示正文从「记录条最后一行 + 屏幕正中浮层」
挪到记录方框第一行（用户「不明显」「挡住汤面」）。判据不是「屏幕上有没有这个东西」，
是**玩家看不见的那一处不算出口**、**盖在汤面（正文）上的那一处是负分**。
量它的是矩形相交，不是肉眼：`hint-check.mjs` / `finder-hint-check.mjs` 里那几条
`overRead` / `overDock` / `aboveLedger`。

**还要给读屏留一个出口。** 印章（一闪就没）、记录条（滚动区）、汤底（画卷里）都只有「看」这一个形态，
所以有一个专门的 `#srVerdict`（`.sr-verdict`）来播报回答 / 解锁 / 提示 / 汤底。
它按读屏专用的老写法做（1×1 + `clip-path: inset(50%)`）：**别改成 `display:none` 或 `width:0`**，
藏起来的 live region 不会被播报；也别把它挪进某个会 `hidden` 的容器里。

### 改画面位置

**图片必须贴着画框，任何视口 / 任何布局都不许错位 —— 这条不是「看着差不多」，是能量的量。**
`tools/frame-fit.mjs` 逐视口逐卷量三个数：当前那张图的矩形 vs `.frame-window` 的内窗矩形、
`strip` 的位移 vs 一个画框宽、封面的 `cover` 缩放因子 vs 两轴尺寸，偏差 > 1px 就报错。
现在 9 个视口 + 「改宽 / 换卷 / 竖横互转 / 键盘态」几条路径 + 44 卷逐卷扫，281 项断言全绿；
补卷之后这一条要重跑 —— 最狠的裁切是《疯人院》（16:9 的封面，被 0.81 的画框裁到只剩 45%，
刚过 0.45 的门槛），它是全库最贴边的一张，动 `--slot-*` 之前先看它。
改 `.slide` / `.strip` / `--slot-*` / `syncLayout` 之后**先跑它**，别靠肉眼。

三条容易掉链子的地方，已经分别钉住了：

1. **画卷宽度 = 滑动步长。** `setOffset` 取的是 `frame.clientWidth`，宽度变了不重算，
   strip 就停在旧步长上，画框里会同时露出上一张的半边（一条竖缝）。见下面「`syncLayout`」那段。
2. **手机横过来不是键盘态。** `keyboardOpen()` 原来只看「可视高度 < 480」，而横屏手机的高度本来就 < 480，
   于是 844×390 被当成键盘态：方向不再重判、停在 `.stage.tall` 上走紧凑布局，
   画卷变成 844×172 的一条横幅，16:9 的封面被裁得只剩 20%。
   现在多一条前置判断 —— **宽度明显大于高度时一定不是键盘**（软键盘只会压高度，不会让宽超过高）——
   横屏走的是横版画廊，裁切可见面积回到 81%。
3. **`.slide` 的份额必须是画框宽的 1/3 且 `object-fit: cover`。** 份额错了会有缝，
   换成 `contain` 会露黑边（那就成「图片比画框小」了）。`frame-fit.mjs` 两条都断言。

左右侧墙画框的可见区域是**量出来的**，不是估的。两组数值写在
`web/styles.css` 的 `.stage` 和 `.stage.tall` 上：

| 变量 | 含义 |
| --- | --- |
| `--slot-*` | 中央金框内窗 |
| `--wing-y` `--wing-h` `--wing-w` | 左右侧墙画框**可见**的那部分内窗 |
| `--frame-pad` | 金框画出来的边比内窗宽出的那截（横版单边 23px） |
| `--dossier-*` | 右侧「询问记录」面板的位置 / 宽度 |
| `--nav-size` `--nav-gap` | 导航箭头尺寸 / 它到金框的气口 |

横版与竖版背景图不是同一张构图，两套值不能混用。
侧墙里的图按容器 4 倍宽渲染再裁掉外面，只露画框可见的那一条。

**导航箭头的位置**：横版是贴着中央金框外侧对称站的
（`--slot-x` − `--frame-pad` − `--nav-gap` − `--nav-size`）。
之所以不贴舞台边，是因为右边那枚会被「询问记录」面板压住 —— 面板底色半透明，
箭头会在下面透出半个影子，看着像坏了。`--nav-gap` 就是两边各留 40px 的墙面色。
竖版另算：记录面板挪到屏幕下方居中，两侧没东西抢位置，所以仍按侧墙画框外沿留气口。

## 性能与内存

2026-09-20 做过一轮「不换观感、只换速度」的打磨。数字都是本机 `curl` 量的。

**服务端（`server.py`，自建部署那条路）**

| 改动 | 量到的东西 |
|---|---|
| `HTTP/1.1` + keep-alive（原来是 stdlib 默认的 HTTP/1.0，**一个请求一条 TCP 连接**） | 一页 40 多个请求：6 个文本请求从 6 条连接变 1 条 |
| 文本类 gzip（css / js / html / json；图与字体不压，它们本来就压过了） | styles.css 87734→27457、app.js 96048→33880、audio.js 29780→9734、index.html 14652→5086、`/api/puzzles` 26370→10484 字节（合计 254KB → 87KB） |
| `board.json` / `stats.json` 内存缓存（**按文件 mtime 失效**） | `/api/board` 每换一卷打一次、`/api/track` 每 20 秒打一次，原来每次都 `read_text + json.loads` 整份文件 |
| 两份数据文件改成「先写 `.tmp` 再 `os.replace`」 | 半截 JSON 不会留在盘上（排行榜被写坏 = 下一次读整份丢） |
| `upsert_score` 整段读-改-写加了锁 | 旧写法没锁：同一卷两人几乎同时结案会**丢一条成绩** |
| `/api/puzzles` 的 18KB 响应体在启动时算好 + 60 秒缓存 | 省掉每次开页的序列化和重发 |
| `request_queue_size` 5 → 128 | 一页并发打四十来个请求，默认 backlog 排满后会丢连接（表现为「有几张封面是空的」） |
| `Handler.timeout = 65` | keep-alive 的连接不会一直挂着占线程 |

三个坑记在这儿，都是这轮踩出来的：

1. **走自定义 gzip 通道时必须用 `self.guess_type()` 定 Content-Type。**
   我们那份 `extensions_map` 只补了 webp / js / css / json / woff2，**`.html` 不在里面** ——
   直接查 map 会掉到 `application/octet-stream`，于是首页被浏览器当文件下载，
   页面停在 `about:blank`，**`tools/suite.py` 里 5 个探针一起「量不到 DOM」**。
   代码是对的，MIME 是错的，报错信息还都在探针自己的 JS 里。
2. **keep-alive 下 POST 必须把请求体读干净。** `/api/stt` 这类不读 body 的分支
   留着没读的字节，会被当成同一条连接上下一个请求的请求行。
   现在 `do_POST` 一进来就整份读掉存着（`_body`），分块请求体直接断连接。
3. **非 UTF-8 的请求体不能再以 `UnicodeDecodeError` 冒出去。** 那会打死处理线程，
   客户端只看到一个没头没尾的 empty reply；现在转成 `JSONDecodeError`，按 400 回。

**线上（`functions/api/[[path]].js`）**：卷宗和题目都是随包发布的死数据，
判题要发的那组 question、`/api/puzzles` 的响应体和它的字符串形式现在都在
**模块级算一次**（Worker 实例会复用），不再每个请求拼一遍；`/api/puzzles` 给了
`max-age=60, stale-while-revalidate=600`。判题本身仍然是一问一次 TypeSafe 请求，这个省不掉。

**前端（`web/app.js` / `web/styles.css`）**

- **每秒那一次 tick 不再空写 DOM。** `#askCount` / `#elapsed` / `#lastMs` 走 `setText()`
  （记着上次写进去的字符串，没变就不碰），**这三个元素的所有写入都在这一处**，
  别在别处直接 `textContent =`，否则那份记忆会失效。
- **页面切到后台就不 tick 了**（表在切走那一刻已经停过），手机上省掉整晚的空转。
- **拖动改成 rAF 节流**：`pointermove` 一帧可能来好几下，而一个 `setOffset` 要写 8 个元素的
  transform。位置先只记在 `dragX` 上，一帧最多落一次 DOM；**松手 / 起推拉动画前必须 `cancelDragMove()`**，
  否则排队那一帧会在动画起来之后按拖动中的位置再写一遍（连 `transition` 都被改成 `none`）。
- **手机上封面预解码有界**：空闲补图从「全库全补」收成前后各 8 卷
  （`IDLE_SPAN`，桌面仍是全补）。手机上那是这个页面最大的一块内存。
- **等待期有反馈**：求灯 / 提问的状态行前 3 秒只是「……」，之后带上秒数
  （`startWait` / `stopWait`，慢网络下能看出它在动，而不是以为点空了）。
- **排行榜分了「取不到」和「尚无结案」** —— 以前断网时显示「尚无结案」，看着像榜是空的。
- **给读屏留了一个出口**：`#srVerdict`（`.sr-verdict`，1×1 + `clip-path` 裁干净）。
  这游戏全是「看」的（印章一闪、记录条一列、汤底在画卷里），没有它读屏用户问完一句
  什么都收不到。**别改成 `display:none`** —— 藏起来的 live region 不会播报；
  `tools/hint-check.mjs` 的 `findText()` 会显式跳过它，免得它把「提示行被藏起来了」这种真故障盖成假绿。

## 手机端两套布局

竖版画廊是两套坐标系：上半（卷号 85vw、汤面 102vw）按**宽度**走，底部那一摞（输入条 4vh 起往上）
按**高度**走。屏幕一矮就没有第三空间了 —— 汤面和记录面板抢同一段，键盘再一顶整页就糊。

所以竖屏有两套布局，由 `app.js` 的 `syncLayout()` 二选一：

| | 用在哪 | 长什么样 |
|---|---|---|
| 画廊（`.stage.tall`） | `height >= 1.375 × width + 180` | 原来那套：画卷居中、侧墙、印章、底部记录面板 |
| 紧凑（`.stage.compact`） | 屏幕矮了，或者键盘弹起 | flex 六段：顶栏(卷号+标题+换卷+声音) / 画卷横幅 / 汤面 / 记录 chip 条 / 状态 / 输入条 |

那个门槛不是拍脑袋的比例，是从 CSS 常量解出来的：
汤面 `top 102vw` + `max-height min(30vw,24vh)` 最低触到 132vw，
底部一摞固定占 `4vh + 100px`，记录面板保底 64px（面板头 + 一条记录，往下滚）——
解 `H - 0.04H - 100 - 132vw - 64 - 8 >= 0` 得 `H >= 1.375w + 180`。

2026-09-20 门槛从 269 降到 180（用户实抓 354×676 对比 440×956：画廊才是对的，
小屏也要画框）。**门槛和 `.stage.tall .dossier` 的 max-height 保底是同一道方程
（保底 64px => 门槛 +180），两头必须一起改**，否则面板长满记录时会压住汤面
（compact-scan 的画廊态断言按 max-height 上限量这条）。原来按 150px 面板推的
+269 会把 354×676 / 390×725 / 535×912 全推进紧凑态。
已知仍进不了画廊的：360×640 / 375×667 / 412×732 / 400×600 / 480×720 / 320×520 / 820×1180。
**改这几条 CSS 常量（`--slot-y` / `.read` / `.dossier` 的 `bottom`）时，
记得回头改 `app.js` 的 `GALLERY_MIN_RATIO` / `GALLERY_MIN_PAD`，然后跑一遍 `fit-scan.mjs`。**

**探针里也抄了这两个数，抄了就一定会过期。** `tools/fit-scan.mjs` 有一份
`GALLERY_MIN_RATIO` / `GALLERY_MIN_PAD` 的拷贝（它要算「该不该紧凑」）；
`tools/hint-check.mjs` 的紧凑态测试高度 `COMPACT_H` 现在**从同一道方程算出来**
（原来是写死的 730）。2026-09-20 门槛从 269 降到 180 时这两处没跟着改，
`suite.py` 里 fit-scan 与 hint-check 白红了一轮 —— 报的却是「图片位置」之类的界面症状，
很容易以为是刚改的画布代码坏了。**再看到这两个脚本红，先对一眼门槛数字。**

紧凑态里有两点是踩过坑才加上的，别顺手删掉：

- **导航、声音、记录不能藏**。回答只渲染在 `.ledger` 里（外加一个 2.4s 的印章），
  把记录藏了就等于「问完看不到回答」。所以紧凑态把导航/声音绝对定位进顶栏、
  把记录压成一条横向可滚的 chip 条（每条 = 问句 + 结论，最新的在最左）。
- **`.frame-window` 要保持 `position: relative`**。印章是它的绝对定位子元素，
  改成 `static` 印章会改挂到 `.stage` 上、跑到屏幕正中间糊在汤面上。
- **背景那幅展厅画在紧凑态必须压暗（`.stage.compact .hall::after`），画卷自带金线细边**。
  那幅画是按横版等比舞台画的，金框在画面中央 1/3；紧凑态舞台是任意比例 + `cover` 裁切，
  画出来的框投影随比例漂移，永远对不齐全幅画卷 —— 535×912 实抓：框底梁从画卷下缘
  露出来、框的两侧又被画卷盖住，看着就是「图片超出相框」。压暗后框不再可辨，
  画卷那圈 1px 金边就是它自己的框，**框跟着图走，任何比例都贴着**。

#### 紧凑态的版面：画卷吃富余，「画卷 + 汤面」当一整块

原先画卷是固定的一条横幅（`min(38vw, 32%)`，390 宽只有 148px），富余全被推给下面的
`.read`，汤面靠 `margin: auto 0` 在那一大块里居中 —— 结果是「上下一两百像素空带 +
两行 14px 小字」，配上顶栏 / 记录条 / 输入条三条贯通的实心 1px 横线，
整页念起来就是一张课程表（实测 390×730：汤面上下各 198px 空白）。

现在改成：

- **画卷自己长起来吃富余**（`height: min(78vw, 44%)`，`flex: 0 1 auto` 让它真的挤不下时
  才给汤面让位），汤面改成「贴着头像往下、自己多高就多高」（上限 46% 封顶，超长在内部滚）。
- **富余落在这一块的外面，而不是在里面掏两个洞**：`.frame-window` 挂 `margin-top: auto`、
  `.read` 挂 `margin-bottom: auto`，上下两个 auto 外边距把富余对分，
  「画卷 + 汤面」作为一整块在顶栏与记录条之间居中。`compact-scan.mjs` 会断言这两个留白对称。
- **三条实心横线换成「两头淡、中间亮」的金线**（`.plaque/.dossier/.dock::after`），
  分段还在，但不再是网格。
- **汤面 14px → 16px**。14px 宋体在手机上偏小，正是「汤面字很小」的由来；
  16px 也正好是 iOS 里不会再触发输入框自动放大的那一档。

**改 `position` 类型时必须把四个偏移量一起显式置 `auto`。** 为了挂那条金线的 `::after`，
紧凑态的 `.plaque` / `.dossier` / `.dock` 从 `static` 改成了 `relative` ——
而横版 / 竖版遗留的 `top: 68.8%`（`.plaque`）、`top: 85vw`（`.stage.tall .plaque`）、
`bottom: 4.6%`（`.dock`）、`bottom: 4vh`（`.stage.tall .dock`）在 `relative` 下不再是空话，
会真的把这两条推走（实测顶栏被推到 332px 处、跟画卷叠在一起，输入条也被顶起来压住记录条）。

#### `syncLayout` 里那条「宽度变了也要重算偏移」

画卷宽度 = 三张立绘的滑动步长（`setOffset` 取 `frame.clientWidth`）。
原先只在**换布局**（画廊 ↔ 紧凑）时才重算，宽度变了但模式没变就不管 ——
于是 strip 停在旧步长上，画框里会同时露出上一张的半边，一条竖着的接缝。
手机在微信里打开时最容易撞上（webview 宽度会变、高度变化更大，但两边都还在紧凑态）。
现在改成「宽度变了或换了布局都补一下」，但**只在宽度变化时**才补：
可视高度在手机上会因为地址栏收放频繁抖动，每次抖都 `setOffset` 会把玩家正在拖的那一下打断。

#### 点输入框不能丢焦点（手机上「卡一下，然后输入不了」）

2026-09-20 用户报：手机上点输入框**输入法会闪退** —— 卡一下，然后整句话敲不进去，
顶部搜剧本和底部问句两个框都有。`tools/mobile-input-check.mjs` 就是照着这条写的，
量出来是同一类事、三个不同来源，**全都是「聚焦之后可见性或布局变了」**：

| 探针量到的现场 | 原因 |
|---|---|
| 搜剧本框 `focusin` 之后紧跟 `focusout`、activeElement 变 BODY | 键盘弹起把可视视口压到 560 以下 → `syncLayout` 翻紧凑态 → `.stage.compact .finder .finder-box { display: none }` **把正在输入的框藏了** |
| 名字框的 `focusout` 出现在 `vv.resize` **之前** | `@media (max-height: 560px) { .stage.tall .dossier { display: none } }` 是纯 CSS，比 JS 翻布局**更早**生效 —— 整块记录面板连着里面的输入框一起没了 |
| 本来就处在紧凑态时怎么点都没事 | 键盘弹起不需要翻布局，没有「变」这一步 |

修法（都在 `web/app.js` 的 `syncLayout` 一带）：

1. **翻之前先揭出口**（`revealFocusOutlet`）：有焦点的输入框要是会被紧凑态藏起来，
   先把它在紧凑态里的出口打开（`#findInput` → 加 `.finding`，紧凑态的搜索框本来就在浮层里；
   这也正好符合「紧凑态的搜索就是个浮层」这个语义）。
2. **翻完把焦点接回来**（`keepFocus`）：真掉了就 `focus({ preventScroll: true })` 接回去。
3. **没有出口的输入框，正在输入时干脆不翻**（`COMPACT_INPUT_OUTLET`）：`#playerName` 在紧凑态
   整行是 `display: none`，翻过去等于丢焦点 —— 它聚焦期间既不藏面板也不翻布局（stage 挂 `.naming`）。
4. `styles.css` 里 `@media (max-height: 560px)` 那条**加了 `.naming` 例外**（见上表第 2 行）。

三条别踩的坑：

- **不要想在 `pointerdown` 里「提前」把布局切好。** 试过，是错的：切布局会让手指底下那个输入框
  当场挪位置，等 touchend 合成 click 时坐标已经不在它身上 —— 点击直接落空，比原来的毛病更坏
  （探针第 1、3 组当场红）。
- **`focus` 处理器里那个 `stage.classList.contains("kb")` 是死守卫**：`.kb` 全项目没人加
  （CSS 里也没有），所以它恒为假 —— 每次聚焦 260ms 后都真的滚了一下 `scrollIntoView`，
  而那一下正好落在输入法弹起的时刻。现在按真正的那件事判（`compactOn`）。
- **加任何新输入框，先回答「它在紧凑态落在屏幕上哪一块」**（和求灯、计时同一条规矩）。
  答不上来就先别加；`COMPACT_INPUT_OUTLET` 那张表就是这句话的落地。

还有一条是**探针自己的坑**：模拟键盘的高度不能写「保底 320px」—— 横屏 844×390 扣掉 320 只剩
70px 可视区（真机上不存在这种键盘），舞台按 3:2 缩成 105 宽、搜剧本框塌成 0 宽，
量出来是个**假故障**，查了半天才发现是参数不现实。现在按 `min(45%, 420px)` 算。
